# Fighter

2D-файтинг на C++23 и SFML 3. Учебный проект.

> **Статус: ранний прототип / каркас.** Архитектура (события, модули, система
> координат) написана и работает, но геймплея пока почти нет: бойцы умеют только
> двигаться и прыгать, удары и урон не реализованы. Подробности — в разделе
> [Текущее состояние](#текущее-состояние).

---

## Что это

Каркас файтинга, построенный вокруг трёх независимых модулей, которые общаются
через систему событий:

- **PhysicsModule** — гравитация, трение, сопротивление воздуха, упругие
  столкновения, пространственная сетка (`SpatialGrid`) для broad-phase.
- **GraphicsModule** — отрисовка через `sf::RenderTexture`, очередь `Drawable`,
  менеджер текстур.
- **FightController / Fight / Fighter** — игровая логика: бойцы, ввод, таймер
  раунда, состояния матча.

Связующие элементы:

- **EventManager** (`include/event.hpp`) — самописная система событий с
  type-erased обработчиками (`EventHandler<T, Args...>`). Подписывает методы
  объектов на события клавиатуры, мыши и тика времени.
- **CoordinateSystem** (`include/coordinate_system.hpp`) — разделение мировых
  (физика) и экранных (графика) координат, камера с зумом/поворотом. Доступна
  как глобальный объект `g_coordSystem`.

## Структура

```
include/   — заголовки (20 файлов)
source/    — реализация (11 .cpp)
assets/    — текстуры (фоны, игроки, объекты)
logs/      — логи (создаются в рантайме)
Makefile   — сборка под Windows (MinGW) и macOS (clang)
*.md       — проектная документация (см. ниже)
```

Объём: ~2730 строк в `source/` + `include/`, ~240 строк тестов.

### Ключевые классы

| Класс | Файл | Роль |
|-------|------|------|
| `EventManager`, `Event<Args...>` | `event.hpp` | система событий |
| `Entity` | `physics.hpp` | физическое тело (позиция, скорость, масса, состояние) |
| `SpatialGrid` | `physics.hpp` | broad-phase для коллизий |
| `PhysicsModule` | `physics.hpp` | интегрирование, столкновения |
| `Drawable` / `DrawableSprite` / `DrawableText` | `graphics.hpp` | графические примитивы |
| `GraphicsModule` | `graphics.hpp` | окно, очередь отрисовки |
| `GameObject` | `game_object.hpp` | `Entity` + `DrawableSprite`, синхронизация физика↔графика |
| `CoordinateSystem` | `coordinate_system.hpp` | конвертация мир↔экран, камера |
| `FightController` | `fight_controller.hpp` | состояние матча, маршрутизация событий |
| `Fight` | `fight.hpp` | один бой: два бойца + сцена |
| `Fighter` / `FighterInfo` | `fighters.hpp` | боец и его параметры |
| `Hitbox` / `Rect` | `hitbox.hpp`, `geometry.hpp` | хитбоксы и AABB-коллизии |

`GameObject` наследуется и от `DrawableSprite`, и от `Entity` — графика и физика
живут в одном объекте, а `updateGraphicsPosition()` переносит мировую позицию на
экран через `g_coordSystem`.

## Сборка

Требуется **SFML 3** и компилятор с C++23.

> ⚠️ **Makefile прибит к конкретной версии SFML.** Путь
> `/opt/homebrew/Cellar/sfml/3.0.0/` (цель `mac`) у вас, скорее всего, не
> совпадёт с установленной версией. На этой машине стоит SFML 3.0.2, и сборка
> падает с `'SFML/Graphics.hpp' file not found`. Поправьте путь под `brew
> --prefix sfml` (или `/opt/homebrew/opt/sfml`) перед сборкой.

```bash
# macOS
make mac        # релиз  -> ./run_mac
make mac_dbg    # отладка (-g -D MDEBUG)

# Windows (MinGW)
make            # -> run.exe
make debug
```

Запуск: `./run_mac`

## Управление

| Клавиша | Действие |
|---------|----------|
| `A` / `D` | влево / вправо |
| `W` / `Space` | прыжок |
| `S` | присесть *(заглушка)* |
| `Q` | удар рукой *(заглушка)* |
| `E` | удар ногой *(заглушка)* |

Раскладка задаётся в `FighterInfo::KeyControls` (`include/fighters.hpp`). Сейчас
**обоим** бойцам отправляется один и тот же ввод (`Fight::keyPressed` дёргает и
левого, и правого) — второй раскладки/игрока за вторым набором клавиш нет.

## Текущее состояние

Что работает:

- окно, рендер фона, платформы и двух спрайтов-бойцов;
- система событий, тик времени (~100 Гц), цикл `main`;
- движение и прыжок левого/правого бойца;
- гравитация и жёсткое ограничение по краям экрана.

Чего ещё нет (заглушки или не подключено):

- **удары и урон** — `attack_with_hand()`, `attack_with_leg()`, `sit()` пустые;
- **HP** — поле `Fighter::hp` не инициализируется, логика победы в
  `Fight::timeEvent` работает с мусором;
- **коллизии между объектами** — у `GameObject` не задаётся `Hitbox`, поэтому
  `SpatialGrid` не кладёт бойцов в ячейки и `checkHitboxCollision` ни с чем не
  срабатывает; «пол» держится только на клампе в `applyConstraints`;
- **меню/паузы/финальный экран** — `gui.hpp`, `PauseMenu`, `FinalMenu`
  закомментированы;
- загрузка сцены из файла (`// TODO: Load Scene from txt file`).

## Известные проблемы

- **Сборка**: путь к SFML в `Makefile` захардкожен под 3.0.0 (см. выше).
- **Согласованность координат**: гравитация направлена в `-y`
  (`gravity = Vec2(0,-10)`), а пол в `applyConstraints` — это `y > WINDOW_HGT`
  (ось вниз). `worldToScreen` отражает `y`. Конвенции «верх/низ» в физике,
  ограничениях и графике между собой не согласованы — поведение падения сейчас
  условное.
- **Утечки**: `new Background`, `new BaseBlock`, обработчики событий и т.п. не
  освобождаются. Для прототипа некритично, но течёт.
- **Логирование**: макросы `MESSAGE`/`MSG` в `DSL.hpp` открывают и закрывают
  файл лога на **каждое** сообщение, а лог пишется в горячем цикле (каждый кадр,
  на каждый объект). Это ощутимо бьёт по производительности; вырубается через
  `MESSAGE_CLEAR`/перекомпиляцию без `MDEBUG`-веток.
- **Копипаста**: `FightController::mouseMoved` вызывает `mousePressed`.
- **Бинарники в репозитории**: `run_mac` и `run_mac.dSYM/` закоммичены —
  лучше вынести в `.gitignore`.
- **Тесты** (`test_physics.cpp`, `test_coordinates.cpp`) не подключены к
  `Makefile` и собираются вручную.

## Документация

В репозитории лежит набор подробных `.md`-файлов (`PROJECT_ARCHITECTURE.md`,
`FLOW_DIAGRAM.md`, `PHYSICS_*`, `COORDINATE_SYSTEM_GUIDE.md` и др.). Они полезны
как описание задумки, но писались в маркетинговом тоне и местами **опережают
реальность**: описывают API и возможности как «готовые к продакшену», тогда как
часть из этого — заглушки или планы. Сверяйтесь с кодом и с разделом
[Текущее состояние](#текущее-состояние). Навигатор по этим файлам —
[`ARCHITECTURE_INDEX.md`](./ARCHITECTURE_INDEX.md).
