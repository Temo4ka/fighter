## 1. Общие правила

Неизвестное поле — ошибка: опечатка в ключе не превращается молча в значение по умолчанию.

- Сообщение об ошибке называет файл, поле и значение.
- Части тела пишутся как в `getBodyPartName()` (`Head`, `Torso`, `ForearmR`…), слоты — как в
  `getEquipmentSlotName()` (`Head`, `MainHand`…), ступени реакции — как в `getReactionLevelName()`
  (`None`, `Touch`, `Flinch`, `Stagger`, `Knockback`, `Knockdown`).
- Ключи новых файлов — `snake_case`. Старые файлы (`combat.json`, `rigs/`, `poses/`) — `camelCase`;
  их не переименовываем, чтобы не ломать загрузчики.
- Всё, что относится к бою, читается при создании `Battle`, поэтому `F5` в песочнице подхватывает правки.

| Файл | Что | Кто читает |
|---|---|---|
| `rigs/*.json` | тело: части, суставы, управление, руки, предметы в руках | `rig::loadRigDef` |
| `poses/*.json` | клипы поз | `anim::loadClip` |
| `combat.json` | правила боя вне тел | `combat::loadCombatTuning` |
| `moves/*.json` | удары: что делает удар (без кнопки и оружия) | `combat::loadMoves` |
| `movesets/*.json` | наборы движений: ввод → удар, наследование, пары, блок, стойка | `combat::MoveLibrary::load` |
| `input.json` | запасные направления, окно одновременного нажатия | `combat::loadInputRules` |
| `items/*.json` | предметы: общие поля и компоненты | `stats::loadItemCatalog` |
| `fighters/*.json` | листы бойцов | `stats::loadFighterSheet` |
| `reactions.json` | сила удара → урон и ступень, накопление, блок | `combat::loadReactionTable` |
| `balance.json` | статы → физический профиль | `stats::loadBalanceTable` |
| `visuals.json` | картинки, эффекты, HUD | `render::loadVisuals` |
| `ui.json` | экраны меню | `ui` (при запуске и по `F5`) |
| `stand.json` | стенд удара | `combat::loadStandConfig` |
| `editor.json` | пороги редактора поз (необязателен) | `editor::loadEditorConfig` |

## 2. Проверка данных

`fighter_app --check-data` проверяет каждый файл правилами его формата, а затем ссылки между файлами.

Как запускать — [TOOLS.md](TOOLS.md), раздел 6. Внутри файла действуют правила его формата (неизвестные поля,
диапазоны, повтор ввода в наборе). Перекрёстные проверки:

| Что | Правило |
|---|---|
| `balance.json`, `combat.json`, `reactions.json`, `input.json`, `stand.json`, `editor.json`, `rigs/*.json` | файл читается без ошибок |
| `moves/*.json` | `chain_to` называет существующие удары; `clip` и `close_clip` — существующие клипы, и они читаются; у клипа есть `active` и `strikers`; удар с `uses_weapon` бьёт предплечьем (оно среди `strikers`, правило `combat::findStrikeProblems`) |
| `movesets/*.json` | каждый ввод называет существующий удар; `inherit` называет набор и не замыкается в кольцо; `pair` — два набора без пар, и других наборов на ту же пару нет; набор `unarmed` есть; клипы `block.clips` и `stance` существуют |
| `poses/` | есть клипы, которые бой играет сам: `stance`, `walk`, `crouch`, `crouch_walk`, `block_high/mid/low`, `flinch`, `stagger`, `knockback`; у них и у клипов блока наборов нет `pelvisX` |
| `items/*.json` | `id` уникальны во всех файлах; `moveset` называет существующий набор; `weapon.angle_deg` — в пределах `weapon.wristLimits` каждого рига |
| ключ `Weapon` в клипах | угол каждого ключа загруженных клипов — в пределах `weapon.wristLimits` рига (иначе риг молча обрезал бы его) |
| `fighters/*.json` | предметы существуют, влезают в слоты, суммарная масса в пределах |

Не проверяются: `visuals.json`, `ui.json` и картинки (их читают рендер и меню), числа «на ощущение» — только ссылки
и структура. Пустую активную фазу или клип без ударных частей проверка считает ошибкой: такой удар не попадёт.

## 3. `rigs/*.json` — тело

Части тела, суставы и все параметры управления телом; сейчас один риг — `humanoid`.

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `root` | часть | нет | `Pelvis` | корень тела; всегда кинематический |
| `parts` | массив | да | — | формы частей, все 13, каждая один раз (ниже) |
| `joints` | массив | да | — | суставы: у каждой части, кроме корня, ровно один родитель (ниже) |
| `kinematic` | список частей | нет | только корень | части, которые ставит код; каждая висит на кинематической части |
| `passThrough` | список частей | нет | пусто | физические части, проходящие сквозь такие же части соперника |
| `unjam` | список частей | нет | пусто | физические части, которые уступают, застряв в сопернике |
| `yieldPose` | `{часть: градусы}` | нет | — | поза уступающей руки; только для частей из `unjam` |
| `weapon` | объект | нет | — | предметы в руках (ниже) |
| `control` | объект | нет | значения кода | параметры управления; все ключи необязательны, смысл и значения — [TUNING.md](TUNING.md), разделы 2–3, 6–8, 11–12 |

**Часть** (`parts[]`): `part`, `shape` и поля формы в эталонной позе — стоит прямо, руки вниз, лицом вправо,
метры от точки на полу под телом.

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `part` | часть | да | — | какая часть |
| `shape` | `capsule` / `circle` / `box` | да | — | форма |
| `from`, `to` | `[x, y]` | у `capsule` | — | концы оси капсулы |
| `center` | `[x, y]` | у `circle` и `box` | — | центр |
| `halfExtents` | `[x, y]` | у `box` | — | полуразмеры прямоугольника |
| `radius` | м | нет | 0 | радиус капсулы и круга, скругление прямоугольника |
| `friction` | число | нет | 0,6 | трение (стопы 1,0; пол 0,9) |

**Сустав** (`joints[]`):

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `child`, `parent` | часть | да | — | часть и её родитель (родитель описан раньше) |
| `anchor` | `[x, y]` | да | — | точка шарнира в эталонной позе |
| `limits` | `[от, до]`, градусы | да | — | пределы угла, по порядку, не шире ±175° |
| `strength` | доля | нет | 1,0 | доля момента мотора у шарнира |

**`weapon`**:

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `part` | часть-капсула | нет | `ForearmL` | предплечье основной руки |
| `offPart` | часть | нет | другое предплечье | предплечье другой руки; не равно `part` |
| `angle` | градусы | нет | 0 | угол запястья, если его не задали клип, стойка и предмет; внутри `wristLimits` |
| `width` | м, > 0 | нет | 0,05 | ширина оружия без `width_m` предмета |
| `grip` | м, ≥ 0 | нет | 0,1 | хват второй руки двуручного оружия от кулака |
| `wristLimits` | `[от, до]`, градусы | нет | −120…120 | пределы запястья, по порядку, не шире ±175° |
| `wristStrength` | доля, ≥ 0 | нет | 1,0 | доля момента STR у запястья |

**`control`**, реакция таза и колен на удар ([TUNING.md](TUNING.md), раздел 7):

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `pelvisTiltPerStrength`, `pelvisMaxTilt` | рад, ≥ 0 | нет | 0,7; 0,2 | наклон таза на силу и плечо удара; предел |
| `pelvisSinkPerStrength`, `pelvisMaxSink` | м, ≥ 0 | нет | 0,08; 0,06 | проседание таза; предел |
| `pelvisSinkReach` | м, > 0 | нет | 0,5 | где проседание сходит на нет |
| `pelvisHitHertz` | Гц, > 0 | нет | 3 | пружина наклона и проседания |
| `pelvisHitDampingRatio` | (0…1] | нет | 0,5 | её затухание |
| `kneeBucklePerStrength`, `kneeMaxBuckle` | рад, ≥ 0 | нет | 0,8; 0,35 | подламывание колена; предел |
| `kneeBuckleReach` | м, > 0 | нет | 0,4 | где подламывание полное |
| `kneeBuckleHertz` | Гц, > 0 | нет | 4 | пружина колена |
| `kneeBuckleDampingRatio` | (0…1] | нет | 0,7 | её затухание |

## 4. `poses/*.json` — клипы

Один файл — один клип; имя файла — его имя. Как клипы играются — [MECHANICS.md](MECHANICS.md), раздел 3.

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `loop` | да/нет | нет | нет | цикл |
| `duration` | с, > 0 | да | — | длина клипа |
| `active` | `[от, до]`, с | нет | нет | активная фаза удара; 0 ≤ от ≤ до ≤ `duration` |
| `strikers` | список частей | нет | пусто | ударные части |
| `stiffness` | × | нет | 1,0 | жёсткость моторов во время клипа |
| `allowMove` | да/нет | нет | да | можно ли идти во время клипа |
| `blendIn`, `blendOut` | с, ≥ 0 | нет | из `blends` в `combat.json` | переход в клип и из него |
| `keys` | массив `{"t", "pose"}` | да | — | ключи; `pose` — `{часть: градусы}` и необязательный `Weapon` |
| `pelvisX` | массив `{"t", "x"}` | нет | нет | дорожка сдвига таза, м вперёд по направлению взгляда |

Правила:
- Ключей хотя бы один; первый — в `t = 0`; ключи по времени и не позже `duration`.
- Каждый ключ задаёт один и тот же набор суставов; `Weapon` — либо во всех ключах, либо ни в одном, в пределах ±180°.
- Клип с ключами ног — действие ногами; без них клип играет только верх тела ([MECHANICS.md](MECHANICS.md), раздел 2.5).
- `pelvisX`: первый ключ `t = 0, x = 0`, ключи по времени, не позже `duration`, `|x| ≤ 1` м; у цикла дорожки нет.
- Файл пишется в виде редактора поз ([TOOLS.md](TOOLS.md), раздел 7.15).

Бой сам играет `stance`, `walk`, `crouch`, `crouch_walk`, `block_high`, `block_mid`, `block_low`, `flinch`,
`stagger`, `knockback`; остальные клипы называют удары, наборы и блоки.

## 5. `combat.json` — правила боя

Параметры боя вне тел: дистанции, порог попадания, расталкивание, усталость, цепочки, ноги, переходы, физика.

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| числовые поля верхнего уровня | число | нет | значения кода | [TUNING.md](TUNING.md), разделы 2, 10, 11; `maxChainLength`, `physicsSteps`, `physicsSubSteps` — целые ≥ 1 |
| `legStep` | объект | нет | значения кода | шаги в действие ногами; `stanceAfterStop` — строка `"mirror"` или `"authored"` ([TUNING.md](TUNING.md), раздел 6) |
| `blends` | объект | нет | значения кода | `default`, `strikeStartupShare`, `rules` — правила `{"from", "to", "sec"}`; виды: `stance`, `walk`, `crouch`, `crouchWalk`, `block`, `strike`, `reaction`, `any` ([TUNING.md](TUNING.md), раздел 5) |

Значения проверяются: расстояния и скорости положительны, доли — в своих пределах
(`exhaustedSpeedScale`, `crouchWalkSpeedScale` — (0, 1]; `walkLiftScale`, `blockBackSpeedScale`,
`exhaustedRecoverFraction` — [0, 1]), длительности не отрицательны.

## 6. `moves/*.json` — удары

Один файл — один удар; имя файла — его id (`moves/jab.json` → `jab`).

Id попадает в события (`StrikeStarted::MoveId`), в `FighterView::MoveId` и в статистику `BattleResult`.
Удар описывает, **что** он делает; какой ввод его начинает и для какого оружия — дело набора движений,
поэтому один удар можно дать нескольким оружиям.

```json
{ "clip": "sword_slash", "uses_weapon": true, "damage": 1.4, "min_reaction": "Flinch", "stamina": 14,
  "tags": ["mid", "swing"], "ai": { "role": "heavy" } }
```

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `clip` | имя клипа | да | — | клип: позы, активная фаза, ударные части |
| `uses_weapon` | да/нет | нет | нет | удар оружием: к нему применяются `speed_scale` и `power_scale` оружия (удар ногой вооружённого — без них) |
| `damage` | ≥ 0 | да | — | множитель урона (О.4) |
| `min_reaction` | ступень | нет | `None` | самая слабая реакция на чистое попадание; `Knockdown` нельзя |
| `stamina` | ≥ 0 | да | — | расход выносливости при начале удара (О.13) |
| `close_clip` | имя клипа | нет | — | клип вплотную |
| `close_range_m` | м, ≥ 0 | с `close_clip` | — | дистанция между тазами, ближе которой играется `close_clip` |
| `chain_to` | список id | нет | пусто | удары, отменяющие восстановление после чистого попадания (О.7); удар цепочки выбирается вводом по набору, нет его в списке — цепочки нет |
| `tags` | список строк | нет | пусто | метки: высота `high` / `mid` / `low` (не больше одной; для ИИ, на блок не влияет), вид `punch`, `kick`, `swing`, `thrust`, `bash`… |
| `ai` | объект | нет | — | намерение для ИИ, бой его не читает: `range_m` — `[min, max]` между тазами, м; `role` — `poke`, `heavy`, `close`, `low`, `anti_close`…; `weight` — частота среди ударов одной роли (по умолчанию 1) |

Скорость удара задают клип и бой, а не файл удара ([MECHANICS.md](MECHANICS.md), раздел 3.3).

## 7. `movesets/*.json` — наборы движений

Один файл — один набор; имя файла — его id. Набор предмета называет поле `moveset` предмета.

```json
{ "inherit": "unarmed", "stance": "stance_sword",
  "moves": { "Light": "sword_cut", "Heavy": "sword_slash", "Forward+Heavy": "sword_thrust", "Special": "sword_spin" },
  "block": { "clips": { "High": "block_high_sword", "Mid": "block_mid_sword", "Low": "block_low_sword" } } }
```

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `inherit` | id набора | нет | — | родитель: всё, чего нет в наборе (ввод, поле блока, стойка), берётся у него; без циклов |
| `pair` | `[основная, другая]` | нет | — | набор действует вместо набора основной руки, когда в руках ровно такая пара (меч + щит, два кинжала) |
| `moves` | `{ввод: id удара}` | нет | — | таблица ввода |
| `stance` | имя клипа | нет | у родителя, иначе `stance` | стойка покоя набора; без `pelvisX`; нет файла — ошибка с именем набора |
| `block` | объект | нет | — | блок набора (ниже) |

**Какой набор у бойца.** Набор пары предметов, если он есть, иначе набор основной руки, иначе другой
(кроме щита: щит в другой руке ударов не даёт), иначе `unarmed` — он обязателен.

- С оружием `Light` — лёгкий удар оружием (`sword_cut`, `hammer_bash`), а не джеб.
- Набор `shield` (удар `shield_bash`) действует, когда щит в основной руке.
- Пара `sword_shield` наследует `sword` (и его стойку `stance_sword`); `unarmed` стоит в общей `stance`.
  Ходьба `walk` общая и накладывается поверх стойки набора.

**Ввод.** Кнопки: `Light`, `Heavy`, `Kick`, `Special` (клавиши — README). Направление — относительно соперника:
`Neutral` (можно не писать), `Forward`, `Back`, `Up`, `Down`, `UpForward`, `UpBack`, `DownForward`, `DownBack`.

- Несколько кнопок через `+` — нажатые вместе (`Light+Heavy`); направление — одно.
- Один ввод в наборе — один раз (`Forward+Heavy` и `Heavy+Forward` — одно и то же).

**Выбор удара.** Перебираются направления: зажатое, затем его запасные из `input.json`, затем `Neutral`.
Для каждого — набор, затем его родители. Внутри набора выигрывает подходящая строка с наибольшим числом кнопок
(все её кнопки зажаты, хотя бы одна нажата сейчас).

- Из приседа сразу начинается удар, найденный по направлению вниз (`Down+Heavy` меча — низкий рубящий);
  остальные — после вставания (`crouchStandUpSec`).
- `Down+Kick` не назначен ни в одном наборе — он доходит до `Kick`.

**`block`** — блок набора с родителями; чего нет ни в одном — из `reactions.json` и зон по умолчанию.

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `damage_scale` | 0…1 | нет | `reactions.json` | доля урона сквозь блок |
| `max_level` | ступень | нет | `reactions.json` | самая сильная реакция на заблокированный удар; `Knockdown` нельзя |
| `stamina_scale` | ≥ 0 | нет | 1 | множитель `stamina_per_strength` (щит держит дешевле) |
| `clips` | `{"High", "Mid", "Low"}` | нет | `block_high` / `block_mid` / `block_low` | клип стойки блока по зонам; `null` выключает зону (у двуручного меча `"Low": null` — Down+Block только приседает); клипы читаются из `poses/` |
| `covers` | `{зона: [части]}` | нет | О.2: верх — голова, середина — корпус и руки, низ — таз и ноги | какие части закрывает зона |

## 8. `input.json` — ввод

```json
{ "combo_window_sec": 0.05,
  "fallbacks": { "UpForward": ["Up"], "UpBack": ["Up"], "DownForward": ["Down"], "DownBack": ["Down"] } }
```

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `combo_window_sec` | с, 0…0,5 | нет | 0,05 | окно одновременного нажатия. Нажатие, из которого в наборе бойца (с родителями, по тем же направлениям) ещё может получиться сочетание, ждёт остальные кнопки не дольше окна; иначе удар начинается сразу. То же для запроса цепочки |
| `fallbacks` | `{направление: [направления]}` | нет | — | какие направления пробовать после зажатого, по порядку, без повторов; `Neutral` пробуется последним всегда и не пишется |

## 9. `items/*.json` — предметы

Предмет — общие поля и необязательные компоненты; новые предметы добавляются только данными.

Файл — объект `{"items": [...]}`; файлов сколько угодно, `id` уникальны во всех.

```json
{ "items": [
  { "id": "iron_helmet", "name": "Iron helmet", "slot": "Head", "covers": ["Head"], "mass_kg": 2.5, "armor": 0.3 },
  { "id": "greatsword", "name": "Greatsword", "slot": "MainHand", "two_handed": true, "mass_kg": 3.5, "moveset": "greatsword",
    "weapon": { "reach_m": 1.0, "speed_scale": 0.85, "power_scale": 1.4, "width_m": 0.07, "angle_deg": 83, "grip_m": -0.15 } },
  { "id": "wooden_shield", "name": "Wooden shield", "slot": "OffHand", "mass_kg": 3.0, "armor": 0.3, "moveset": "shield",
    "shield": { "length_m": 0.35, "width_m": 0.45, "angle_deg": 0, "poise_bonus": 0.2 } } ] }
```

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `id` | строка | да | — | id предмета, непустой |
| `name` | строка | нет | `id` | имя для меню и панели |
| `slot` | слот | да | — | `Head`, `Body`, `Hands` (перчатки), `Legs`, `Feet`, `MainHand` (основная, передняя рука — L), `OffHand` (другая, задняя — R) |
| `two_handed` | да/нет | нет | нет | занимает обе руки; только со `slot` `MainHand` |
| `covers` | список частей | кроме предметов в руке | — | части, которые предмет утяжеляет и защищает. У предмета в руке поля нет: он лежит на предплечье держащей руки (у двуручного — на обоих) |
| `mass_kg` | кг, 0…30 | да | — | масса; делится поровну между `covers` |
| `armor` | 0…1 | нет | 0 | доля поглощаемого урона |
| `moveset` | id набора | нет | — | набор движений предмета; только у предмета в руке |
| `weapon` | объект | нет | — | компонент «оружие»; только у предмета в руке |
| `shield` | объект | нет | — | компонент «щит»; только у предмета в руке |

**`weapon`** (О.12) — оружие как тело на запястье ([MECHANICS.md](MECHANICS.md), раздел 6.2):

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `reach_m` | м, 0…1,5 | да | — | насколько оружие выступает за кулак: поверхность капсулы кончается на `reach_m` дальше поверхности кулака |
| `speed_scale` | 0,25…4 | да | — | множитель скорости ударов оружием (`uses_weapon`); тяжёлое < 1 |
| `power_scale` | 0,25…4 | да | — | множитель урона ударов оружием |
| `width_m` | м, 0…0,2 | нет | `weapon.width` рига | ширина клинка или древка: и картинка, и физика (радиус капсулы — половина). Дробящее рисуется древком 0,6 и головой 2 ширины |
| `angle_deg` | градусы, −180…180 | нет | `weapon.angle` рига | хват по умолчанию: угол к предплечью, когда ни клип, ни стойка не задают `Weapon`; в пределах `wristLimits` рига |
| `grip_m` | м, −0,5…0,5 | нет | `weapon.grip` рига | у двуручного: где держит вторая рука, вдоль оружия от кулака основной; отрицательное — позади кулака (двуручный меч: −0,15). Генератор рисует рукоять двуручного меча длиной `−grip_m` + 0,07 м |

**`shield`** — пластина по центру предплечья держащей руки ([MECHANICS.md](MECHANICS.md), раздел 6.5):

| Поле | Тип | Обязательное | По умолчанию | Смысл |
|---|---|---|---|---|
| `length_m` | м, 0…1,2 | да | — | вдоль предплечья |
| `width_m` | м, 0…1,2 | да | — | поперёк |
| `angle_deg` | градусы, −180…180 | нет | 0 | угол к предплечью |
| `poise_bonus` | 0…2 | нет | 0 | стойкость × (1 + `poise_bonus`), когда щит в основной руке |

Картинки предметов в руках — [ART.md](ART.md) и раздел 13.

## 13. `visuals.json` — картинки, эффекты, HUD

Какие картинки у частей и предметов, эффекты попаданий и размеры HUD; бой о картинках не знает.

Файл читает `render::loadVisuals`; `F5` перечитывает его и картинки. Испорчен — остаются прежние картинки
и параметры, ошибка — в журнале панели и в логе. Все поля необязательны; неизвестный ключ — ошибка с полным
путём (`skins.a.smoth`). Пути — от корня проекта. Правила для самих картинок — [ART.md](ART.md).

```json
{ "pixels_per_meter": 64, "default_skin": "placeholder_smooth", "style": "smooth",
  "styles": { "smooth": { "skin": "placeholder_smooth" },
              "pixel": { "skin": "placeholder_pixel", "pixel_art": { "scale": 0, "letterbox": true } } },
  "background": "assets/backgrounds/bg.jpeg",
  "skins": { "placeholder_pixel": { "dir": "assets/placeholders/pixel/humanoid", "items_dir": "assets/placeholders/pixel/items",
                                    "pixels_per_meter": 32, "smooth": false } },
  "items": { "iron_helmet": {}, "short_sword": { "origins": { "ForearmR": [0.5, 0.5] } } },
  "effects": { "hit_flash": { ... }, "camera_shake": { ... }, "dust": { ... } },
  "hud": { ... } }
```

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `pixels_per_meter` | px/м | 64 | пикселей картинки на метр; скин и предмет могут переопределить |
| `default_skin` | id скина | — | скин бойца, для которого приложение не выбрало другой; должен быть в `skins` |
| `style` | id стиля | — | стиль при запуске; должен быть в `styles`; обязателен, если есть `styles` |
| `styles.<id>.skin` | id скина | `default_skin` | скин бойцов этого стиля |
| `styles.<id>.pixel_art` | объект | нет | пиксельный режим (T.4); нет — мир рисуется в разрешении окна |
| `styles.<id>.pixel_art.pixels_per_meter` | px/м | плотность скина стиля | плотность картинки низкого разрешения |
| `styles.<id>.pixel_art.scale` | целое 0…16 | 0 | увеличение; 0 — наибольшее, при котором высота вида влезает в окно |
| `styles.<id>.pixel_art.letterbox` | да/нет | да | сохранить высоту вида, остаток окна чёрный; нет — закрыть окно, вид чуть больше |
| `background` | путь | — | фон; растягивается с сохранением пропорций; нет файла — ровный цвет |
| `skins.<id>.dir` | путь | — | картинки частей: `<dir>/<Часть>.png` (13 файлов, имена — `getBodyPartName()`) |
| `skins.<id>.items_dir` | путь | — | накладки снаряжения этого скина: `<items_dir>/<id предмета>/<Часть>.png` |
| `skins.<id>.pixels_per_meter` | px/м | `pixels_per_meter` | плотность картинок скина и его накладок |
| `skins.<id>.smooth` | да/нет | да | сглаживание при масштабировании и повороте; для пиксель-арта — нет |
| `items.<id>` | объект | — | уточнения для предмета; `{}` — предмет просто перечислен (по списку генератор рисует накладки) |
| `items.<id>.dir` | путь | `<items_dir скина>/<id>` | свой каталог накладок |
| `items.<id>.pixels_per_meter` | px/м | плотность скина | своя плотность накладок |
| `items.<id>.origins` | `{часть: [x, y]}` | `[0.5, 0.5]` | точка привязки накладки — доли ширины и высоты от левого верхнего угла; ставится в центр части |
| `effects`, `hud` | объекты | значения из [TUNING.md](TUNING.md), раздел 15 | эффекты попаданий и размеры HUD в пикселях окна |

**Какой скин у бойца** решает приложение (поле `Skins` в `App`): пусто — скин стиля, иначе `default_skin`.
Накладки — по снаряжению бойца (`BattleConfig`: `Loadout`, `covers` предметов).

**Предмет в руке** рисуется только на держащем предплечье (двуручный — на основной руке); картинка одной руки
годится для другой (щит с `ForearmR.png` в левой руке рисуется ею же, с её `origins`).
**Оружие** — не накладка: одна картинка `<каталог предмета>/Weapon.png` для любой руки на теле оружия.

**Чего не хватает — не ошибка.** Нет картинки части — она рисуется капсулой размера `PartTransform::Size`;
нет накладки — предмет не рисуется; неизвестный скин — все части капсулами; нет картинки оружия — капсула его размера.
В лог — одно предупреждение на скин или предмет со списком частей; на панели — строка `render`.
