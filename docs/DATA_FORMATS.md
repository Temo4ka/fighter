# Форматы данных боя

Что лежит в `data/`, кто это читает и что значит каждое поле. Зафиксировано в волне 0
фазы 2 (задача 2.0.3, docs/DEVELOPMENT_PLAN.md); меняется только через ревью.
Как подбирать значения на сеансах настройки — в [TUNING.md](TUNING.md).

## Общие правила

- Неизвестное поле — ошибка: опечатка в ключе не должна молча превращаться в значение
  по умолчанию. Сообщение об ошибке называет файл, поле и значение.
- Части тела пишутся как в `getBodyPartName()` (`Head`, `Torso`, `ForearmR`…), слоты —
  как в `getEquipmentSlotName()` (`Head`, `MainHand`…), ступени реакции — как в
  `getReactionLevelName()` (`None`, `Touch`, `Flinch`, `Stagger`, `Knockback`, `Knockdown`).
- Ключи новых файлов — `snake_case` (как в `items/` и `fighters/`). Старые файлы
  (`combat.json`, `rigs/`, `poses/`) пишутся в `camelCase`; их не переименовываем,
  чтобы не ломать загрузчики без нужды.
- Всё, что относится к бою, перечитывается при создании `Battle`, поэтому `F5` в
  песочнице подхватывает правки.

| Файл | Что | Кто читает | Состояние |
|---|---|---|---|
| `rigs/*.json` | тело: части, суставы, параметры управления, руки, которые уступают (`unjam`), и их поза отступа (`yieldPose`, углы в градусах), предметы в руках (`weapon`: `part`, `offPart`, `angle`, `radius`, `grip`) и пружина хвата двуручного (`control`: `grip*`, TUNING.md, раздел 12) | `rig::loadRigDef` | есть |
| `poses/*.json` | клипы поз; кроме клипов ударов бой обязательно читает `stance`, `walk`, `crouch`, `crouch_walk`, блоки и реакции; клип с ключами ног — действие ногами, без них играет только верх тела (TUNING.md, раздел 3б); необязательная дорожка `pelvisX` — сдвиг таза ударом (выпад; TUNING.md, раздел 3а); необязательные ключи позы `Weapon` и `WeaponOff` — запястья, угол оружия к предплечью: `Weapon` — руки, которой клип бьёт (или основной), `WeaponOff` — другой (TUNING.md, раздел 3в) | `anim::loadClip` | есть; новые клипы — задача 2.2 |
| `combat.json` | параметры боя вне тел (расстояния, порог попадания, усталость, попадание в щит `shieldHitMargin`, остановка удара о соперника, шаги физики и жёсткость контактов, допустимое перекрытие бойцов, поза покоя после остановки, докатывание и короткий шаг, шаги в действие ногами); целые — `maxChainLength`, `physicsSteps`, `physicsSubSteps`; объекты — `blends` (переходы позы) и `legStep` (шаги в действие; `stanceAfterStop` — строка `"mirror"` или `"authored"`), см. TUNING.md, разделы 3а и 3б | `combat::loadCombatTuning` | есть |
| `items/*.json` | предметы: общие поля и компоненты (защита, набор движений, оружие, щит) | `stats::loadItemCatalog` | есть |
| `fighters/*.json` | листы бойцов; одноручный предмет можно переложить в другую руку | `stats::loadFighterSheet` | есть |
| `moves/*.json` | удары: что делает удар (без кнопки и оружия) | `combat::loadMoves` | есть |
| `movesets/*.json` | наборы движений: ввод → удар, наследование, наборы на пару предметов, блок | `combat::MoveLibrary::load` | есть |
| `input.json` | запасные направления ввода, окно одновременного нажатия | `combat::loadInputRules` | есть |
| `reactions.json` | сила удара → урон и ступень реакции, накопление, блок | `combat::loadReactionTable` | есть |
| `balance.json` | статы → физический профиль | `stats::loadBalanceTable` | работает (2.4) |
| `visuals.json` | картинки частей тела и предметов, эффекты, размеры HUD | `render::loadVisuals` | есть (2.5) |
| `stand.json` | настройки стенда удара: статы бойца и манекена, расстояние, ожидания | `combat::loadStandConfig` | есть (М.4) |

## Проверка данных — `fighter_app --check-data`

`./build/debug/src/app/fighter_app --check-data` читает всё в `data/` без окна, печатает **все** найденные
проблемы (по строке: `файл: поле, значение`) и завершается с кодом 0, если их нет, и 1, если есть. Тест
`checkData: the real data directory has no problems` гоняет ту же проверку по настоящей `data/`.
Реализация — `combat::checkData()` (`src/combat/data_check.hpp`): каждый файл читается теми же
загрузчиками, что и в бою, по одному, поэтому сломанный файл не прячет проблемы остальных; внутри файла
действуют правила его формата (неизвестные поля, диапазоны, повтор ввода в наборе — `Light+Heavy` и
`Heavy+Light` один ввод). Перекрёстные проверки:

| Что | Правило |
|---|---|
| `balance.json`, `combat.json`, `reactions.json`, `input.json`, `stand.json`, `rigs/*.json` | файл читается без ошибок |
| `moves/*.json` | `chain_to` называет существующие удары; `clip` и `close_clip` — существующие файлы в `poses/` и читаются; у клипа есть активная фаза (`active` не пустое) и ударные части (`strikers`); удар с `uses_weapon` бьёт рукой (предплечье среди `strikers`), потому что оружие держит предплечье (попадание оружием — попадание предплечьем) |
| `movesets/*.json` | каждый ввод называет существующий удар; `inherit` называет набор и не замыкается в кольцо; `pair` — два набора без пар, и ни один другой набор не задан на ту же пару; есть набор `unarmed`; клипы блока (`block.clips`) и стойки (`stance`) существуют |
| `poses/` | есть клипы, которые играет бой сам: `stance`, `walk`, `crouch`, `crouch_walk`, `block_high/mid/low`, `flinch`, `stagger`, `knockback`; у них и у клипов блока наборов (`block.clips`) нет дорожки `pelvisX` — таз двигают только удары (сама дорожка — первый ключ `t = 0, x = 0`, по времени, в пределах клипа, `\|x\| ≤ 1` м, не у цикла — проверяется при чтении клипа) |
| `items/*.json` | `id` уникальны во всех файлах; `moveset` предмета называет существующий набор; `weapon.angle_deg` — в пределах запястья рига (`weapon.wristLimits` каждого `rigs/*.json`) |
| запястья (`Weapon`, `WeaponOff` в позах) | у загруженных клипов (удары, стойки, блоки, клипы боя) углы `Weapon` и `WeaponOff` каждого ключа — в пределах `weapon.wristLimits` рига: за пределами риг молча обрезал бы их. Каждый из ключей — либо во всех ключах клипа, либо ни в одном, и в пределах ±180° (проверяется при чтении клипа) |
| `fighters/*.json` | предметы существуют, влезают в слоты, суммарная масса в пределах |

Что проверка не делает: `visuals.json`, `ui.json` и картинки (их читают рендер и меню), числа «на ощущение»
(скорость, урон) — только ссылки и структуру. Пустую активную фазу или клип без ударных частей она
считает ошибкой: такой удар никогда не попадёт.

## `stand.json` — стенд удара

Настройки стенда (`fighter_app --stand`, TUNING.md, раздел 14) и функции `combat::measureMove()`; ключи в
`snake_case`, все необязательные, неизвестный ключ — ошибка, значение вне диапазона — ошибка с именем поля.
Это не правила боя: только то, на чём измеряют.

```json
{ "attacker": {"strength": 10, "dexterity": 10, "constitution": 10},
  "dummy": {"strength": 10, "dexterity": 10, "constitution": 10},
  "dummy_distance_m": 0.8, "use_move_range": true, "settle_sec": 0.5,
  "start_timeout_sec": 1.0, "move_timeout_sec": 5.0, "repeat_pause_sec": 0.8,
  "no_dummy_distance_m": 12.0 }
```

## Замеры удара — `combat::measureMove()`

`measureMove({.MoveId, .WeaponId, .WithDummy, .DataDir})` проводит один удар без окна: боец (слева,
оружие `WeaponId` в основной руке) нажимает ввод, которым его набор запускает удар, манекен (справа) стоит
без ввода. Результат `MoveMeasure`:

- `StartupSec` / `ActiveSec` / `RecoverySec` — сколько секунд атака проводит в фазах (реальное время:
  ловкость, скорость оружия и усталость уже учтены);
- `Paths` — путь ударной части: её кончик на каждом шаге. Кончик — тот конец длинной оси части, что дальше
  от таза; у предплечья с оружием в ударе «оружием» (`uses_weapon`) — точка на длину `reach_m` оружия
  дальше. Клип могут играть зеркально (другая нога впереди, оружие в другой руке): пути ведутся для
  `strikers` клипа и их зеркальных частей, остаётся та, чей кончик прошёл дальше;
- `ReachM` — **досягаемость**: наибольшее расстояние вперёд (к сопернику) от таза бойца **в момент начала
  удара** до кончика в активной фазе. Взят таз, а не передняя нога: по тазу работают расстояния боя (спейсинг,
  `ai.range_m`); таз в момент начала — чтобы шаг вперёд в самом ударе считался досягаемостью, а не сдвигом
  точки отсчёта; выпад клипа (`pelvisX`) входит в досягаемость;
- `PelvisPath`, `PelvisForwardM`, `PelvisBackM`, `PelvisEndM` — ход таза в ударе: путь таза по шагам,
  дальше всего вперёд и назад от таза в начале удара (по направлению взгляда) и где он в конце удара
  (дорожка `pelvisX`; смещение после удара остаётся); в сводке — `pelvis +0.25 m, ends +0.10 m`, если таз
  сдвинулся;
- `Hit`, `HitTimeSec`, `HitPart`, `Damage`, `Reaction`, `Blocked` — первое попадание по манекену.

Без `WeaponId` боец безоружен, а если удара нет в наборе `unarmed`, берётся первый предмет каталога, чей
набор его запускает. Неизвестный удар или предмет, предмет, который нельзя взять в руку, и удар, который не
запускает ни один ввод набора, — `std::runtime_error` с именем удара или предмета. Манекен стоит в середине
`ai.range_m` удара (если есть и `use_move_range`), иначе на `dummy_distance_m`; без манекена (`WithDummy =
false`) соперник стоит далеко (`no_dummy_distance_m`), и ничто не останавливает удар.

## `moves/*.json` — удары

Один файл — один удар; имя файла — его id (`moves/jab.json` → `jab`). Id попадает в
события (`StrikeStarted::MoveId`), в `FighterView::MoveId` и в статистику
`BattleResult`. Удар описывает, **что** он делает; какой ввод его начинает и для какого
оружия — дело набора движений (`movesets/`), поэтому один удар можно дать нескольким
оружиям.

```json
{
    "clip": "sword_slash",
    "uses_weapon": true,
    "damage": 1.4,
    "min_reaction": "Flinch",
    "stamina": 14,
    "tags": ["mid", "swing"],
    "ai": { "range_m": [0.7, 1.1], "role": "heavy" }
}
```

| Поле | Обязательно | Что значит |
|---|---|---|
| `clip` | да | клип `poses/<clip>.json`: позы, активная фаза, ударные части |
| `uses_weapon` | нет | удар оружием: к нему применяются `speed_scale` и `power_scale` оружия. По умолчанию `false` (удар ногой вооружённого бойца — без них) |
| `damage` | да | множитель урона удара (О.4), ≥ 0 |
| `min_reaction` | нет | самая слабая реакция на чистое (не заблокированное) попадание, сколь бы слабым оно ни было; `Knockdown` нельзя. По умолчанию `None` |
| `stamina` | да | расход выносливости при начале удара (О.13), ≥ 0 |
| `close_clip` | нет | клип вплотную: играется вместо `clip`, если в момент начала удара тазы бойцов ближе `close_range_m` (задача 2.3) |
| `close_range_m` | с `close_clip` | дистанция между тазами, м, ближе которой играется `close_clip`; ≥ 0 |
| `chain_to` | нет | id ударов, которые могут отменить восстановление этого удара после чистого попадания — короткие цепочки (О.7); окно и длина — `chainWindowSec`, `maxChainLength` в `combat.json`. Удар цепочки выбирается вводом по набору бойца; если выбранного удара нет в списке — цепочки нет |
| `tags` | нет | метки: высота `high` / `mid` / `low` (не больше одной; для ИИ, на блок не влияет — его решает физика, см. «Блок» ниже), вид `punch`, `kick`, `swing`, `thrust`… и любые метки, которые ищут реакции или ИИ |
| `ai` | нет | намерение для ИИ (2.9), бой его не читает: `range_m` — `[min, max]` дистанция между тазами, м; `role` — `poke` (быстрый тычок), `heavy`, `close` (вплотную), `low`, `anti_close`…; `weight` — как часто выбирать среди ударов одной роли (по умолчанию 1) |

**Скорость.** Клип задаёт номинальные тайминги. Бой ускоряет его в
`PhysicalProfile::AttackSpeedScale` раз, удар оружием — ещё в `speed_scale` оружия (и
замедляет при усталости). Отдельной нижней границы у удара нет (решение 2026-10-05): скорость
ограничена только коридором DEX (`attack_speed_min`/`attack_speed_max` в `balance.json`) и
таймингами клипа. Ориентир О.7: джеб 0,15–0,20 с, сильный 0,3–0,4 с, DEX сдвигает на ±25 %.

## `movesets/*.json` — наборы движений

Один файл — один набор; имя файла — его id. Набор предмета в руке называет его поле
`moveset` (`items/`). Набор бойца: набор на пару предметов в руках, если такой есть, иначе
набор основной руки, иначе другой (кроме щита: щит в другой руке ударов не даёт, решение 2026-10-08), иначе
`unarmed` — он обязателен. С оружием `Light` — лёгкий удар оружием (решение 2026-10-08), а не
унаследованный джеб. Набор щита (`shield`, с ударом `shield_bash`) действует, когда щит в основной руке.

```json
{
    "inherit": "unarmed",
    "moves": {
        "Light": "sword_cut",
        "Heavy": "sword_slash",
        "Forward+Heavy": "sword_thrust",
        "Light+Heavy": "sword_spin"
    },
    "block": {
        "damage_scale": 0.1,
        "clips": { "Mid": "block_mid_sword" }
    }
}
```

| Поле | Что значит |
|---|---|
| `inherit` | набор-родитель: всё, чего нет в этом наборе (ввод или поле блока), берётся у него. Без циклов |
| `pair` | `[набор основной руки, набор другой руки]`: этот набор действует вместо набора основной руки, когда в руках ровно такая пара (решение 2026-10-08: отдельный набор на пару — меч + щит, два кинжала) |
| `moves` | ввод → id удара. Ввод — направление и кнопки через `+` |
| `stance` | имя клипа стойки покоя набора (`poses/<имя>.json`); необязательное. Нет в наборе — берётся у родителя (`inherit`), нет ни у кого — общий `stance`. Боец стоит в ней, из неё идёт ходьба и к ней возвращаются ноги и руки после удара и блока; ходьба (`walk`) общая, она накладывается на стойку. Клип без дорожки `pelvisX`; нет файла — ошибка с именем набора и поля |
| `block` | блок этого набора; все поля необязательные |

**Ввод.** Кнопки: `Light`, `Heavy`, `Kick`, `Special` (клавиши — README). Направление —
относительно соперника: `Neutral` (можно не писать), `Forward`, `Back`, `Up`, `Down`,
`UpForward`, `UpBack`, `DownForward`, `DownBack`. Несколько кнопок — нажатые вместе
(`Light+Heavy`). Один ввод в наборе — один раз (`Forward+Heavy` и `Heavy+Forward` — одно и то же).

**Выбор удара.** Перебираются направления: держимое, затем его запасные из `input.json`,
затем `Neutral`; для каждого — набор, затем его родители; внутри набора выигрывает
подходящая строка с наибольшим числом кнопок (все её кнопки зажаты, хотя бы одна нажата
сейчас). Из приседа сразу начинается удар, найденный по направлению вниз (`Down+Heavy` меча —
низкий рубящий); остальные — после вставания (`crouchStandUpSec`). `Down+Kick` не назначен (низкий
удар ногой убран, решение 2026-10-08) — он доходит до `Kick`.

**Блок** (`block`): блок бойца — блок его набора с родителями; чего нет ни в одном — из `reactions.json`
(`block.damage_scale`, `block.max_level`), клипы `block_high` / `block_mid` / `block_low` и зоны О.2.
Клипы, названные в `clips`, бой загружает из `poses/` (нет файла — ошибка с именем набора).

Блок решает физика (решение 2026-10-08): удар блокируется, если зона блока закрывает часть тела, которой
он коснулся; метка высоты удара на блок не влияет. Попадание в пластину щита в другой руке (в пределах
`shieldHitMargin` из `combat.json`) блокируется любой зоной.

| Поле | Что значит | Пределы |
|---|---|---|
| `damage_scale` | доля урона, проходящая сквозь блок | 0…1 |
| `max_level` | самая сильная реакция на заблокированный удар; `Knockdown` нельзя | |
| `stamina_scale` | множитель расхода выносливости на принятый удар (`stamina_per_strength` в `reactions.json`): щит держит дешевле | ≥ 0 |
| `clips` | клип стойки блока по зонам: `{"High": ..., "Mid": ..., "Low": ...}`; по умолчанию `block_high` / `block_mid` / `block_low` | |
| `covers` | какие части тела закрывает зона: `{"Mid": ["Head", "Torso", ...]}`; по умолчанию — по О.2 (верх — голова, середина — корпус и руки, низ — таз и ноги) | |

## `input.json` — ввод

```json
{
    "combo_window_sec": 0.05,
    "fallbacks": { "UpForward": ["Up"], "UpBack": ["Up"], "DownForward": ["Down"], "DownBack": ["Down"] }
}
```

| Поле | Что значит |
|---|---|
| `fallbacks` | для направления — какие направления пробовать после него, по порядку, если в наборе нет удара; `Neutral` пробуется последним всегда и не пишется |
| `combo_window_sec` | кнопки, нажатые в пределах этого времени, считаются нажатыми вместе (`Light+Heavy`), с; 0…0,5. Нажатие, из которого в наборе бойца (с родителями, по тем же направлениям) ещё может получиться сочетание, ждёт остальные кнопки не дольше окна; иначе удар начинается сразу. То же для запроса цепочки |

## `items/*.json` — предметы

Предмет — общие поля и необязательные компоненты (решение 2026-10-08: новые предметы —
только данными). Файлов может быть сколько угодно, id уникальны во всех.

```json
{ "id": "iron_helmet", "name": "Iron helmet", "slot": "Head", "covers": ["Head"], "mass_kg": 2.5, "armor": 0.3 }

{ "id": "short_sword", "name": "Short sword", "slot": "MainHand", "mass_kg": 1.2, "moveset": "sword",
  "weapon": { "reach_m": 0.55, "speed_scale": 1.0, "power_scale": 1.15 } }

{ "id": "greatsword", "slot": "MainHand", "two_handed": true, "mass_kg": 3.0, "moveset": "sword",
  "weapon": { "reach_m": 0.95, "speed_scale": 0.85, "power_scale": 1.4 } }

{ "id": "wooden_shield", "slot": "OffHand", "mass_kg": 3.0, "armor": 0.3, "moveset": "shield",
  "shield": { "length_m": 0.35, "width_m": 0.45, "angle_deg": 0, "poise_bonus": 0.2 } }
```

| Поле | Обязательно | Что значит | Пределы |
|---|---|---|---|
| `id` | да | id предмета | непустой |
| `name` | нет | имя для меню и панели; по умолчанию id | |
| `slot` | да | `Head`, `Body`, `Hands` (перчатки), `Legs`, `Feet`, `MainHand` (ведущая, передняя рука — L), `OffHand` (задняя — R) | |
| `two_handed` | нет | занимает обе руки; только со `slot` `MainHand` | |
| `covers` | кроме предметов в руке | части тела, которые предмет утяжеляет и защищает. У предмета в руке поля нет: он лежит на предплечье держащей руки (у двуручного — на обоих) | |
| `mass_kg` | да | масса, делится поровну между `covers` | 0…30 |
| `armor` | нет | доля поглощаемого урона; по умолчанию 0 | 0…1 |
| `moveset` | нет | набор движений, который предмет даёт (`movesets/`); только у предмета в руке | непустой |
| `weapon` | нет | компонент «оружие»; только у предмета в руке | |
| `shield` | нет | компонент «щит»; только у предмета в руке | |

**`weapon`** (О.12):

| Поле | Обязательно | Что значит | Пределы |
|---|---|---|---|
| `reach_m` | да | насколько оружие выступает за кулак, м: поверхность его капсулы кончается на `reach_m` дальше поверхности кулака | 0…1,5 |
| `speed_scale` | да | множитель скорости ударов оружием (`uses_weapon`; тяжёлое оружие < 1) | 0,25…4 |
| `power_scale` | да | множитель урона ударов оружием | 0,25…4 |
| `width_m` | нет | ширина клинка или древка, м: и картинки (генератор плейсхолдеров), и физики — радиус капсулы оружия равен половине. По умолчанию — `weapon.width` рига (`rigs/`, сейчас 0,05). У дробящего оружия древко рисуется в 0,6, голова — в 2 ширины | 0…0,2 |
| `angle_deg` | нет | запястье по умолчанию: угол оружия к предплечью, градусы (0 — продолжает предплечье, как штык; знак как у суставов — положительный против часовой у бойца лицом вправо). Действует, когда ни клип, ни стойка набора не задают запястье этой руки (`Weapon` или `WeaponOff`, TUNING.md, раздел 3в); по умолчанию — `weapon.angle` рига. Должен быть в пределах `weapon.wristLimits` рига (`--check-data`) | −180…180 |

**Оружие — отдельное тело** (не форма предплечья): капсула от кулака наружу на шарнире-запястье. Её
масса — `mass_kg` предмета (у предплечья её столько же меньше, всего боец весит как раньше); попадание
оружием и в оружие — попадание держащим предплечьем (`strikers` клипа — `ForearmL`/`ForearmR`), ударная
масса — рука с оружием (TUNING.md, раздел 3).

**`shield`** — пластина на предплечье держащей руки: часть этого предплечья для физики и попаданий,
по центру предплечья, `length_m` вдоль него и `width_m` поперёк, повёрнутая на `angle_deg`. Что щит
делает, зависит от руки (решение 2026-10-08):

- **в другой руке** (`OffHand`, рядом с оружием или один) — средство блока: попадание в пластину
  блокируется любой зоной блока; ударов не даёт (его `moveset` идёт только в пару, например `sword_shield`);
- **в основной руке** — как оружие: удары его набора (`shield`, `shield_bash`), автоматического блока
  попаданием в пластину нет (блок — по обычным правилам: закрыта ли зоной часть, предплечье), стойкость ×
  `1 + poise_bonus`.

Виды щитов: малый (закрывает корпус; сейчас `wooden_shield`), средний (до колена), большой (во весь рост)
— вид задаётся только размером пластины, отдельного поля нет; средний и большой — позже.

| Поле | Обязательно | Что значит | Пределы |
|---|---|---|---|
| `length_m` | да | вдоль предплечья, м | 0…1,2 |
| `width_m` | да | поперёк, м | 0…1,2 |
| `angle_deg` | нет | угол к предплечью, градусы; по умолчанию 0 | −180…180 |
| `poise_bonus` | нет | прибавка стойкости, когда щит в основной руке: стойкость × (1 + `poise_bonus`); по умолчанию 0 | 0…2 |

**Руки.** Предмет основной руки держит часть `weapon.part` рига (`ForearmL`), другой руки —
`weapon.offPart` (`ForearmR`). Удар оружием (`uses_weapon`) бьёт тем оружием, которое держат ударные
части его клипа (`strikers`); если его держит другая рука, клип играется с переставленными руками
(левая рука вместо правой) — клипы оружия пишутся для одной руки. Двуручный предмет держит основная
рука, вторая берётся за рукоять на `weapon.grip` от кулака (пружина `grip*` в `control` рига) — точку на
теле оружия, поэтому рука идёт за поворотом запястья.

**Оружие в каждой руке** (решение 2026-10-08). Одноручное оружие можно положить и в другую руку
(`{"id": "short_sword", "slot": "OffHand"}`), в том числе рядом с оружием в основной: у каждого — своё
тело и своё запястье, попадание каждым — попадание его предплечьем (основная — `ForearmL`, другая —
`ForearmR`). Набор движений — основной руки (пары `sword`+`sword` нет — бьёт набор `sword`). Удар бьёт
оружием той руки, что указана в `strikers` клипа как есть (клипы оружия написаны для правой — значит,
оружием другой руки, без перестановки рук); только если её оружия нет — с переставленными руками. Если
в `strikers` обе руки, бьют оба оружия. Пример — `fighters/duelist.json`. Двуручный предмет по-прежнему
занимает обе руки. Картинка щита рисуется на держащем предплечье; если
для него картинки нет, берётся картинка другого предплечья (`visuals.json`, `items`). Картинка оружия —
своя, `Weapon.png`, на теле оружия.

## `fighters/*.json` — листы бойцов

```json
{ "name": "Rogue", "stats": { "strength": 9, "dexterity": 15, "constitution": 9 },
  "items": ["leather_cap", "leather_vest", { "id": "short_sword", "slot": "OffHand" }] }
```

Предмет — id или объект `{"id", "slot"}`: так одноручный предмет кладут в другую руку.
Двуручный предмет и предмет не для руки переложить нельзя. Два предмета в одном слоте

## `reactions.json` — что делает попадание

Правила задачи 2.3 (бой), решения О.2, О.4 и ступени реакции.

```json
{
    "location": { "Head": 1.5, "Torso": 1.0, "Pelvis": 0.9, "...": 0.6 },
    "damage_per_strength": 4.0,
    "levels": [
        { "level": "Touch",     "min_strength": 0.3, "stun_sec": 0.0 },
        { "level": "Flinch",    "min_strength": 1.0, "stun_sec": 0.15 },
        { "level": "Stagger",   "min_strength": 2.0, "stun_sec": 0.35 },
        { "level": "Knockback", "min_strength": 3.5, "stun_sec": 0.5 },
        { "level": "Knockdown", "min_strength": 5.5, "stun_sec": 0.0 }
    ],
    "buildup": { "per_strength": 1.0, "decay_per_sec": 1.5, "threshold_drop": 0.08 },
    "block": { "damage_scale": 0.2, "max_level": "Touch", "stamina_per_strength": 3.0 }
}
```

**Сила удара**, м/с — из чего считаются урон и реакция:

    strength = impulse / victim_mass × location[part] × (1 − armor[part])

`impulse` — из `HitEvent`: скорость сближения × приведённая ударная масса двух частей (одна мера для всех ударов, [TUNING.md](TUNING.md), раздел 3), `victim_mass` — масса всего тела жертвы, `armor` — броня
части, в которую попали (`PhysicalProfile::Parts`).

**Урон:** `damage = strength × damage_per_strength × move.damage × weapon.power_scale`
(`power_scale` — только для ударов оружием).

**Ступень:** самая сильная из `levels`, у которой

    strength ≥ min_strength × victim.Poise × max(1 − buildup × threshold_drop, 0.2)

но не слабее `move.min_reaction`. `Poise` — стойкость из профиля (CON, броня), `buildup` —
накопленное: каждое попадание добавляет `strength × per_strength`, со временем убывает
на `decay_per_sec` в секунду. Так серия слабых ударов может привести к пошатыванию, а
нокдаун остаётся редким (О.7). `stun_sec` — сколько боец не может действовать; для
нокдауна время задаёт тело (`rigs/*.json`: `knockdownSec`, `getUpSec`).

| Поле | Что значит |
|---|---|
| `location` | множитель места попадания для каждой части тела (все 13 обязательны) |
| `damage_per_strength` | HP за 1 м/с силы удара |
| `levels` | ступени по возрастанию `min_strength`; каждая из `Touch`…`Knockdown` ровно один раз |
| `buildup.per_strength` | сколько накопления даёт 1 м/с силы |
| `buildup.decay_per_sec` | на сколько накопление убывает за секунду |
| `buildup.threshold_drop` | на какую долю единица накопления снижает пороги |
| `block.damage_scale` | множитель урона при попадании в закрытую зону (О.2) |
| `block.max_level` | самая сильная реакция при блоке (О.2: «касание») |
| `block.stamina_per_strength` | расход выносливости блокирующего за 1 м/с силы |

## `balance.json` — статы в физику

Поля один к одному повторяют `stats::BalanceTable` (src/stats/stats.hpp); формулы —
`stats::computeProfile`. Все поля обязательны, неизвестный ключ — ошибка; значения проверяет
`stats::validateBalanceTable` (массы и базовые значения > 0, «на очко» ≥ 0, `*_min` ≤ `*_max`,
`max_part_armor` в (0, 1]). Загрузка — `stats::loadBalanceTable`; `BalanceTable::getDefaults()`
совпадает с файлом (тест это проверяет). Бой читает файл при создании, `F5` перечитывает.

| Поле | Что значит |
|---|---|
| `base_mass_kg` | масса частей тела при CON = 10 (все 13 имён частей; других имён нет) |
| `mass_per_con` | +доля массы за очко CON выше 10 |
| `base_motor_torque`, `torque_per_str` | сила моторов корпуса и её рост от STR (сила удара и сопротивление ударам; позу держит удерживающий момент тела, `docs/TUNING.md`, раздел 2) |
| `base_motor_gain`, `gain_per_dex` | как быстро моторы выходят на позу, рост от DEX |
| `move_speed_per_dex`, `move_speed_min`, `move_speed_max` | +доля скорости ходьбы за очко DEX и границы множителя |
| `move_speed_per_gear_kg` | −доля скорости ходьбы за кг снаряжения (нагрузка) |
| `attack_speed_per_dex`, `attack_speed_min`, `attack_speed_max` | +доля скорости ударов за очко DEX (±25 % на DEX 0/20, О.7) и коридор множителя (0,75…1,25) |
| `base_hp`, `hp_per_con` | HP и его рост от CON |
| `base_poise`, `poise_per_con` | стойкость (множитель порогов реакции) и её рост от CON |
| `poise_per_armor` | рост стойкости от средней (по массам частей) брони тела |
| `max_part_armor` | потолок брони одной части тела |
| `base_stamina`, `stamina_per_con` | запас выносливости (О.13) |
| `base_stamina_regen`, `stamina_regen_per_con` | восстановление выносливости в секунду при CON = 10 и его рост |

Замедление при нулевой выносливости — правило боя, а не стата: `exhaustedSpeedScale`
в `combat.json`.

## `visuals.json` — картинки, эффекты, HUD

Рендер (задача 2.5) рисует бойцов спрайтами частей тела через список отрисовки. Требования к
самим картинкам (поза, плотность, слои, имена файлов) — в [ART.md](ART.md). Файл читает
`render::loadVisuals`; `F5` перечитывает его и картинки с диска. Если файл испорчен, остаются
прежние картинки и параметры, ошибка — в журнале событий панели и в логе. Бой о картинках
не знает.

```json
{
    "pixels_per_meter": 64,
    "default_skin": "placeholder_smooth",
    "style": "smooth",
    "styles": {
        "smooth": { "skin": "placeholder_smooth" },
        "pixel": { "skin": "placeholder_pixel", "pixel_art": { "scale": 0, "letterbox": true } }
    },

        "placeholder_pixel": {
            "dir": "assets/placeholders/pixel/humanoid",
            "items_dir": "assets/placeholders/pixel/items",
            "pixels_per_meter": 32,

        }
    },
    "items": {
        "iron_helmet": {},
        "short_sword": { "origins": { "ForearmR": [0.5, 0.5] } }
    },
    "effects": {
        "hit_flash": { "min_reaction": "Touch", "duration_sec": 0.06, "radius_m": 0.12 },

```

Все поля необязательны (значения по умолчанию — как в примере, кроме `default_skin`,

Пути — от корня проекта.

| Поле | Что значит |
|---|---|
| `pixels_per_meter` | масштаб: сколько пикселей картинки на метр мира; скин и предмет могут переопределить |
| `default_skin` | скин бойца, для которого приложение не выбрало другой; должен быть в `skins` |
| `style` | стиль при запуске; должен быть в `styles`. Обязателен, если есть `styles` |
| `styles.<id>.skin` | скин, который надевают бойцы этого стиля, если приложение не выбрало другой; должен быть в `skins`. Нет — `default_skin` |
| `styles.<id>.pixel_art` | пиксельный режим рендера (T.4): мир рисуется в картинку низкого разрешения и увеличивается в целое число раз без сглаживания. Нет — мир рисуется в разрешении окна |
| `styles.<id>.pixel_art.pixels_per_meter` | плотность картинки низкого разрешения; нет — плотность скина стиля |
| `styles.<id>.pixel_art.scale` | целое увеличение 0…16; 0 — наибольшее, при котором высота вида влезает в окно |
| `styles.<id>.pixel_art.letterbox` | `true` — сохранить высоту вида в метрах, остаток окна чёрный; `false` — закрыть окно, вид чуть больше |
| `background` | картинка фона; растягивается с сохранением пропорций, чтобы закрыть экран. Нет файла — ровный цвет |
| `skins.<id>.dir` | картинки частей: `<dir>/<Часть>.png` (13 файлов, имена — `getBodyPartName()`). Точка привязки — центр картинки, она ставится в центр части (ART.md) |
| `skins.<id>.items_dir` | накладки снаряжения в стиле этого скина: `<items_dir>/<id предмета>/<Часть>.png`. Так пиксельный скин берёт пиксельные накладки |
| `skins.<id>.pixels_per_meter` | плотность картинок скина и его накладок |
| `skins.<id>.smooth` | сглаживание при масштабировании и повороте (`true`); для пиксель-арта — `false` |
| `items.<id>` | необязательные уточнения для предмета; пустой объект `{}` — предмет просто перечислен (по этому списку генератор плейсхолдеров рисует накладки) |
| `items.<id>.dir` | свой каталог накладок вместо `<items_dir скина>/<id>` |
| `items.<id>.pixels_per_meter` | своя плотность накладок |
| `items.<id>.origins` | точка привязки накладки на части: `{"ForearmR": [x, y]}` — доли ширины и высоты картинки от левого верхнего угла; эта точка ставится в центр части. По умолчанию `[0.5, 0.5]`. Нужна оружию, если картинка не симметрична относительно центра предплечья (ART.md) |
| `effects` | неброские эффекты (О.7, п. 5); пороги — по ступени реакции из `StrikeLanded` (`None`…`Knockdown`, «не слабее»). Смысл каждого параметра — [TUNING.md](TUNING.md), раздел 9 |
| `hud` | размеры полосок, отступы и шрифты интерфейса в пикселях окна (TUNING.md, раздел 9) |

**Какой скин у бойца** — решает приложение, а не бой: поле `Skins` в `App`; пусто — скин стиля,
а если его нет — `default_skin`. Стиль переключается клавишей `F7` (debug) и `--style <id>`.
Накладки — по снаряжению бойца (`BattleConfig`: `Loadout`, `covers` предметов).

Предмет в руке рисуется только на держащем предплечье (двуручный — на основной руке), и картинка одной
руки годится для другой: щит с картинкой `ForearmR.png` в левой руке рисуется ею же (с её `origins`).
**Оружие** — не накладка: у него одна картинка `<каталог предмета>/Weapon.png` для любой руки, она рисуется
на теле оружия сразу после накладок держащего предплечья. Клинок на картинке направлен вниз (−Y): рукоять
сверху, острие снизу; центр картинки — центр капсулы оружия (`Rig::getWeaponTransforms`), ширина клинка —
`width_m`. Нет картинки — оружие рисуется капсулой своего размера.

**Чего не хватает — не ошибка.** Нет картинки части — она рисуется капсулой размера
`PartTransform::Size`; нет накладки — предмет не рисуется; неизвестный скин — все части
капсулами. В лог пишется предупреждение (одно на скин или предмет со списком частей),
на панели — строка `render` (сколько примитивов, спрайтов, капсул вместо картинок и
ненайденных файлов).
