## 1. Debug-сборка: режимы и клавиши

Debug-сборка рисует вместо картинок хитбоксы, силы и скорости, а слева — панель состояния.

Сборка и запуск: `cmake --preset debug && cmake --build --preset debug`, затем
`./build/debug/src/app/fighter_app`. В release отладочного кода в бинарнике нет.

| Клавиша | Действие |
|---|---|
| `F1` / `F2` / `F3` | только отладка (по умолчанию) / отладка поверх картинок / только картинки |
| `F4` | показать или скрыть панель |
| `1`…`9`, `0`, `-`, `=` | включить или выключить категорию отладки (раздел 3) |
| `P` | пауза |
| `.` | один шаг симуляции (ставит на паузу) |
| `[` / `]` | замедлить / ускорить время вдвое (от ×0,1 до ×1) |
| `Backspace` | начать бой заново: создаётся новый бой, файлы боя перечитываются |
| `F5` | перечитать `data/` (риги, позы, параметры боя, `ui.json`, `visuals.json` и картинки) и начать бой заново |
| `F6` | образцы всех категорий отладки |
| `F7` | следующий стиль из `data/visuals.json` (сглаженный / пиксельный); выбор держится и после `F5` |

Если после правки файл не читается (синтаксис, неизвестный ключ, неверное значение), бой не перезапускается.
Продолжается старый бой, а сообщение с именем файла появляется в журнале панели и в логе.

## 2. Панель

Панель — строки «ключ: значение»; у каждого бойца свои строки с префиксом `P1` или `P2`.

Строка живёт, пока её не перезапишут по тому же ключу. Ниже строк — журнал событий.

### 2.1. Общие строки

| Строка | Что показывает |
|---|---|
| `fps` | кадры в секунду и время кадра |
| `tick` | номер шага симуляции и сколько шагов прошло в этом кадре |
| `sim` | `running` / `PAUSED` и масштаб времени |
| `round` | сколько осталось до конца раунда |
| `overlap` | худшее перекрытие частей двух бойцов сейчас (глубина, пара частей) и худшее за бой с временем; `OVER 0.012 allowed` — глубже допуска пары (`armOverlapTolerance` / `overlapTolerance`) |
| `contact walls` | у какой стены каждый боец (`free`, `left wall`, `right wall`), насколько стена не пустила таз в этом шаге (`stopped -0.004 m`), сход с лежащего (`steps off the lying body`) |
| `contact spacing` | что сделало расталкивание тел: `bodies overlap 0.031 m, needs 0.034 m: slows 0.016, pushes 0.011 m (0.66 m/s)` — сколько нужно, сколько из этого замедление, сколько толчок; `, eased` — толчок ограничен плавностью, `, hard` — жёсткий толчок; `one is down` — кто-то лежит |
| `contact posed` | остановка кинематических ног после шага: `P1 strike stopped at 0.43 of the step` (ударная нога вернулась к касанию, доля её движения за шаг), `strike touches` (коснулась, не войдя глубже), `ThighL held back` (нога удержана у соперника), `(3 passes)` — сколько раз проверялись ноги (2 — обычно) |
| `contact push-out` | последнее выталкивание при попадании вплотную |
| `render` | примитивы, спрайты, капсулы вместо картинок, ненайденные файлы |
| `render fx` | сколько эффектов идёт сейчас и кто «дальний» боец |
| `render style` | стиль, увеличение, размер картинки низкого разрешения, плотность, `letterbox` |

Что делает каждая стадия контакта — [MECHANICS.md](MECHANICS.md), раздел 5.

### 2.2. Строки бойца: тело

| Строка | Что показывает |
|---|---|
| `P1 state` | `standing` / `knocked down 0.75 s` / `getting up 0.23 s` |
| `P1 pos` | точка на полу под бойцом, м |
| `P1 pelvis` | контроллер таза: позиция, фактическая скорость, скорость ходьбы, отбрасывание, `clip` — скорость от дорожки `pelvisX`; в нокдауне — `ragdoll (no controller)` |
| `P1 physical` | какие части физические: стоя — корпус, голова, руки; в нокдауне — `all (ragdoll)` |
| `P1 stiffness` | текущая жёсткость моторов |
| `P1 body` | масса, момент моторов, gain, скорость ходьбы |
| `P1 torque` | сумма моментов моторов, Н·м |
| `P1 pose` | насколько корпус отстал от клипа: `error 2 deg (ForearmL)` — самая отставшая часть и угол; `carried: yes` — корпус несётся тазом (в нокдауне и при вставании — `no`); `hold Torso 240 N*m` — самый большой удерживающий момент в этом шаге |
| `P1 facing` | куда смотрит боец и ждёт ли разворот |
| `P1 wall` | какой стены касается; `back against it` — стена за спиной |
| `P1 feet` | стопы: `planted` (стоит на месте), `free`, `steps back` (переставляется под тело) и смещение от позы клипа, м |
| `P1 limbs` | руки: `ok`, `stuck 0.12 s` (застряла в сопернике), `yields 0.10 s` (уступает); `stays down` — нокаут |
| `P1 push` | что сдвинуло таз сверх его плана, м/с: `spacing: slowed` (расталкивание забрало часть сближения), `pushed` (толкают), `wall` (стена не пустила или передала толчок), `push-out` (выталкивание при ударе вплотную); `ragdoll` в нокдауне |
| `P1 posed overlap` | насколько кинематические части бойца вошли в кинематические части соперника |

### 2.3. Строки бойца: статы и снаряжение

Эти строки — итог `stats::computeProfile()` по `data/balance.json` ([MECHANICS.md](MECHANICS.md), раздел 7).

| Строка | Что показывает |
|---|---|
| `P1 build` | статы и оружие |
| `P1 mass` | масса всего тела, масса снаряжения, средняя броня |
| `P1 motors` | момент и gain моторов из статов |
| `P1 speed` | множители ходьбы и ударов |
| `P1 vitals` | HP, стойкость (с пометкой `main-hand shield x1.20`, если щит в основной руке), выносливость и её восстановление |

### 2.4. Строки бойца: бой

| Строка | Что показывает |
|---|---|
| `P1 action` | состояние: `attacking jab (active) speed x1.00`, `blocking high`, `reacting Stagger`, `, exhausted`, `, against the wall` |
| `P1 hp` | здоровье |
| `P1 stamina` | запас, восстановление, `EXHAUSTED` |
| `P1 moveset` | набор движений, его пара и родители, оружие и рука: `sword_shield (pair sword + shield) < sword < unarmed; Short sword in ForearmR` |
| `P1 input` | распознанный ввод (направление и кнопки в окне нажатия) и ожидание сочетания: `Light (waiting for a combination 0.02/0.05 s)` |
| `P1 move` | строка набора, выбравшая последний удар, и откуда она: `Forward+Heavy -> sword_slash (sword)`; оружие удара, `in the other hand`, запрошенная цепочка |
| `P1 block` | блок набора для текущей зоны: `dmg x0.05, max Touch, stamina x0.60; Mid: block_mid, covers Head Torso …` |
| `P1 hands` | что в руках: оружие с шириной `w` и массой тела оружия; щит — `guards` (в другой руке) или `strikes` (в основной); хват двуручного и зазор до рукояти |
| `P1 wrist` | угол оружия к предплечью сейчас и цель, градусы; `pose` — цель из позы; удерживающий момент |
| `P1 poise` | накопление, стойкость и во сколько раз сейчас снижены пороги ступеней |
| `P1 last hit` | последнее полученное попадание: удар, часть тела, сила (м/с), ступень, урон, блок, `on the shield` |
| `P1 contact` | остановка удара о соперника: `holds the contact, 0.05 s left`, `recovers from the contact`, `, jammed in the startup` |
| `P1 lunge` | дорожка `pelvisX`: `sword_thrust: track +0.18 m (ends +0.10), made +0.18 m, moving`; `held back by the opponent` / `held back by a wall` / `stopped at the opponent` / `interrupted by a reaction` — остаток потерян |

### 2.5. Строки бойца: клипы и ноги

| Строка | Что показывает |
|---|---|
| `P1 clip` | клип сверху, его время, скорость и переход |
| `P1 upper` | клип верха тела (`jab 0.12/0.44 s …` или имя стойки) и откуда цель запястья (`wrist from sword_cut`, из стойки или `the weapon's default`) |
| `P1 blend` | идущие переходы позы: `pose walk -> strike 0.05 s, 0.40; legs stance -> walk 0.15 s, 0.70` (вид позы, время перехода, сколько пройдено) или `-` |
| `P1 legs` | слой ног: `walking 0.31`, `, held by the opponent` (соперник держит таз, ноги стоят), `, pushed back`, `held in mid-step at 0.28 (opponent in the way)`, `settling into the stance around FootL (front FootL)`, `resting in the stance (front FootR)`, `action kick (mirrored): step FootR 0.40, then FootL`, `crouch walk 0.20` |
| `P1 stride` | `step planned 0.47 m, made 0.12 m` (полный шаг цикла и сколько прошёл этот); `settle around FootR (set down), pelvis 0.084 m to go`; `rest, last settle 0.112 m` (`rest off the stance` — таз не пустили на место); `re-steps 2, last FootL 0.14 m` |

### 2.6. Журнал событий

Журнал — последние события боя одной строкой каждое.

| Пример | Что значит |
|---|---|
| `P1 jab -> Head: 0.18 m/s -> Flinch, 1.3 dmg (J=10.2 N*s)` | попадание: удар, часть, сила, ступень, урон, импульс |
| `P2 is exhausted`, `battle over: knockout` | выносливость кончилась; бой окончен |
| `spacing pushes apart`, `spacing push over`, `spacing hard push` | расталкивание тел |
| `P1 settles around FootR (set down): pelvis 0.08 m to go, FootL steps`, `P1 settled after 0.11 m` | остановка ходьбы |
| `P1 re-steps FootL: 0.14 m off the pose` | переступание |
| `P1 steps into kick in 0.12 s: …` | шаги в действие ногами |
| `steps FootL with the lunge` | шаг ведущей стопы при выпаде |
| `fx: camera shake (…)`, `fx: dust under P…` | эффекты попаданий |
| `reload: …`, ошибка с именем файла | `F5` и ошибки чтения данных |

## 3. Категории отладки

Категория — группа отладочных примитивов в мировых координатах; клавиша включает и выключает её.

Цвета задаются в одном месте — `src/debug/palette.hpp`.

| Клавиша | Категория | Что рисуется | Цвет |
|---|---|---|---|
| `1` | `Hurtbox` | части тела; оружие — капсула с подписью `weapon` | зелёный (левый боец) / синий (правый) |
| `2` | `Hitbox` | кружок у ударной части — только в активной фазе; на стенде — активная фаза пути | красный |
| `3` | `Block` | полоса перед телом на высоте закрытой зоны; щит — пластина с подписью `shield` | жёлтый |
| `4` | `Static` | пол и стены арены | серый |
| `5` | `Joints` | шарниры, дуги пределов, угол; запястье — как сустав; хват двуручного — линия от рукояти к кулаку с подписью `grip 0.012 m` | белый |
| `6` | `TargetPose` | призрак целевой позы; части, отставшие больше чем на 3°, соединены с ним линией с подписью угла; цель запястья — линия и кружок острия (`wrist +12 deg, target +40`); дуга переступающей или шагающей стопы, крест, куда она встанет, подпись `step FootR 40%` | полупрозрачный голубой |
| `7` | `Motors` | момент мотора в шарнире, в том числе запястья | оранжевый |
| `8` | `Forces` | импульсы попаданий; в нокдауне — толчок падения со скоростью и вращением; стрелки над тазом — что его сдвинуло (`P1 push`); стрелки `track` и `made` дорожки `pelvisX` | пурпурный |
| `9` | `Velocity` | скорости частей; под тазом — стрелки контроллера `v`, отбрасывания `kb` (и выталкивания) и `clip` (дорожка `pelvisX`) | бирюзовый |
| `0` | `Contacts` | точки контакта; крестики под стоящими стопами; уступающие руки (`yields`); остановленная ударная нога (`stopped`) и удержанная (`held back`); кружок на худшем перекрытии (`overlap 0.008`); линия у стены, которой касается боец | ярко-красный |
| `-` | `CoM` | центр масс бойца и опорная точка | белый крест |
| `=` | `Trajectory` | путь ударной части на стенде удара и в редакторе поз; путь таза удара | салатовый |

## 4. Сценарии, скриншоты и тесты

Флаги запуска — таблица в [README](../README.md#флаги-командной-строки); здесь — как ими проверять.

| Задача | Как |
|---|---|
| посмотреть сценарий без клавиатуры | `--demo walk` (P1 ходит), `--demo fight`, `--demo kick` (подходит к P2 и бьёт) |
| сохранить кадр | `--screenshot shot.png --frames 120 --mode both`: кадр 120 сохраняется, программа закрывается |
| образцы категорий | `--showcase` (или `F6`) |
| снять экраны меню | `--menu --keys enter,down,esc`: клавиши меню по одной за кадр; `--round 3` — короткий раунд, чтобы дойти до итогов |
| взять бойцов из данных | `--left knight --right rogue` (`data/fighters/`) |
| сохранить лог | `--log file.log` |

Тесты: `ctest --preset debug` — все; `ctest --preset debug-fast -j8` — без долгих сценарных (тег `[slow]`:
дольше ~3 с в debug, кроме детерминизма); `ctest --preset debug -R "<имя>" --output-on-failure` — один.

**Данные тестов.** Тесты проверяют код, а не настройку: они идут не на `data/`, а на её копии
`build/<пресет>/tests/data`, которую сборка собирает из `data/`, заменяя каталоги, настраиваемые вручную
(`fighters`, `items`, `moves`, `movesets`, `poses`), замороженными копиями из `tests/data`. Риг, `combat.json`,
`reactions.json` и новые файлы берутся из `data/`. Настройка `data/` тесты не ломает; правила о самих данных —
в `--check-data` (раздел 6). Поменялся формат клипа или удара — обновите и `tests/data`. Тест, который правит
данные, берёт копию (`ScratchData` в `tests/combat/scenario.hpp`); временные каталоги — `tests/scratch_dir.hpp`.

| Тест | Что проверяет |
|---|---|
| `tests/combat/test_battle.cpp` | боец стоит 60 с, не сдвигаясь; ходит со скоростью из данных; джеб и удар ногой попадают и раскачивают корпус; тяжёлого отбрасывает меньше; сильный удар сбивает с ног, и боец встаёт |
| `tests/combat/test_fight.cpp` | ступени, блок, выносливость, нокаут, таймер, цепочки. Пороги ступеней большинство тестов задают сами; с `reactions.json` из `data/` работают только «джеб — не выше вздрагивания», блок по зонам, удары оружия и нижняя граница скорости |
| `tests/combat/test_no_passthrough.cpp` | длинные бои: ничто не проходит сквозь соперника |
| `tests/combat/test_spacing_smooth.cpp` | скорость таза не выше 2,5 м/с (вдвое выше ходьбы) и без «туда-обратно» (у стены, навстречу, в стоящего, в тяжёлого, с близкой дистанции); стоящие стопы идущего не скользят |
| `runDataCheck: sound data exits 0 and says so` | `--check-data` по настоящей `data/`: ошибок нет |
| `Every clip of data/poses is written back byte for byte` | редактор записывает каждый клип `tests/data` байт в байт |

## 5. Стенд удара

Стенд — один удар раз за разом перед манекеном, без боя: смотреть и мерить удар.

```bash
./build/debug/src/app/fighter_app --stand sword_slash                 # оружие найдётся по набору
./build/debug/src/app/fighter_app --stand shield_bash --weapon wooden_shield
./build/debug/src/app/fighter_app --stand jab --frames 120 --screenshot jab.png
```

Каждый заход — новый бой, поэтому манекен каждый раз стоит на месте. Неизвестный удар или предмет —
сообщение и код выхода 1, окно не открывается. `F5` перечитывает удар, клип, предмет и `stand.json`
и начинает заново; конец захода тоже перечитывает данные.

| Что видно | Где |
|---|---|
| путь ударной части | категория `=` (`Trajectory`); активная фаза — красным (`Hitbox`) |
| досягаемость | крест в самой дальней точке активной фазы с подписью `reach … m at … s`; крест у таза — откуда она считается |
| попадание | крест у манекена |
| ход таза удара | путь таза (`Trajectory`), в сводке `pelvis +0.25 m, ends +0.10 m` |
| `stand move` | удар, клип, ввод |
| `stand set` | набор движений |
| `stand weapon` | оружие |
| `stand result` | фазы в секундах, досягаемость, попал или нет; событие в журнале после каждого захода |

Пути последнего законченного захода остаются на экране, пока следующий не начнёт двигаться.
Досягаемость считается от таза в начале удара и включает выпад `pelvisX`; с оружием — от острия.
Настройки стенда — `data/stand.json` ([DATA_FORMATS.md](DATA_FORMATS.md#15-standjson--стенд-удара)).

**Замер для тестов — `combat::measureMove()`.** Тот же удар без окна:
`measureMove({.MoveId, .WeaponId, .WithDummy, .DataDir})`. Боец слева с оружием `WeaponId` в основной руке
нажимает ввод, которым набор запускает удар; манекен справа стоит без ввода.

| Поле `MoveMeasure` | Что значит |
|---|---|
| `StartupSec`, `ActiveSec`, `RecoverySec` | время фаз атаки в реальных секундах (ловкость, оружие, усталость учтены) |
| `Paths` | кончик ударной части на каждом шаге: дальний от таза конец части; у предплечья в ударе оружием — на `reach_m` дальше. Ведутся `strikers` и их зеркальные части, остаётся та, что прошла дальше |
| `ReachM` | досягаемость: дальше всего вперёд от таза **в момент начала удара** до кончика в активной фазе |
| `PelvisPath`, `PelvisForwardM`, `PelvisBackM`, `PelvisEndM` | путь таза, дальше всего вперёд и назад от начала и где таз в конце удара |
| `Hit`, `HitTimeSec`, `HitPart`, `Damage`, `Reaction`, `Blocked` | первое попадание по манекену |

Досягаемость берётся от таза, а не от передней ноги: по тазу работают расстояния боя (расталкивание, `ai.range_m`).
Таз в момент начала — чтобы шаг вперёд в самом ударе считался досягаемостью.

Без `WeaponId` боец безоружен; если удара нет в наборе `unarmed`, берётся первый предмет каталога, чей набор его
запускает. Неизвестный удар или предмет, предмет не для руки, удар без ввода в наборе — `std::runtime_error` с именем.
Манекен стоит в середине `ai.range_m` удара (если оно есть и `use_move_range`), иначе на `dummy_distance_m`.
Без манекена (`WithDummy = false`) соперник стоит на `no_dummy_distance_m`, и ничто не останавливает удар.

## 6. Проверка данных

`--check-data` читает всё в `data/` без окна и печатает все проблемы.

```bash
./build/debug/src/app/fighter_app --check-data
```

Каждая проблема — строка `файл: поле, значение`; предупреждение — с `warning:` впереди. Код выхода 0 —
ошибок нет (предупреждения могут быть), 1 — есть. Предупреждение — вероятная ошибка, которую игра всё же
играет: при настройке её можно временно оставить.
Каждый файл читается теми же загрузчиками, что и в бою, по одному: сломанный файл не прячет проблемы остальных.
Реализация — `combat::checkData()` (`src/combat/data_check.hpp`), `data/editor.json` проверяет `app::runDataCheck`.
Что именно проверяется — [DATA_FORMATS.md](DATA_FORMATS.md#2-проверка-данных).

## 7. Редактор поз

Окно для правки клипов `data/poses/*.json` числами и мышью, с физическим превью. Только в debug-сборке.

Это редактор чисел: ощущения по-прежнему подбираются на стенде и в бою.

### 7.1. Запуск

```bash
FIGHTER_ROOT=$PWD ./build/debug/src/app/fighter_app --pose-editor sword_cut --weapon short_sword
```

| Аргумент | Что значит |
|---|---|
| `<клип>` | клип из `data/poses/`; без него — общая стойка `stance` с голыми руками |
| `--weapon <предмет>` | предмет из `data/items/` в основной руке; без него — голые руки |
| `--screenshot <файл>` | сохранить кадр редактора (проверка отрисовки) |

Командная строка задаёт только первый выбор; остальное выбирается в окне (панель Open, 7.6).

Окно: панели и шрифт (JetBrains Mono 12 px) уменьшены (`UiScale` 0,85 в `app/pose_editor.cpp`).
Фигура показана мельче (в высоту окна помещается 2,3 м), чтобы панели её не закрывали.

### 7.2. Призрак

Призрак — цель клипа: поза из ключей по `RigDef` без физики (прямая кинематика), тело стоит на полу стопами.

- В руке предмет: оружие — капсула от кулака с углом `Weapon` к предплечью (если клип его не задаёт — угол предмета),
  щит — пластина на предплечье.
- Клип задаёт не все суставы. Остальное призрак берёт как игра: первый ключ стойки набора оружия
  (`stance_sword` и др., без оружия — `stance`), поверх — клип в выбранный момент (`anim::sampleClip`).
- Клип, у которого `strikers` — предплечье другой руки, призрак играет с переставленными руками, как боец;
  панель Clip пишет об этом. Слайдеры правят ключи так, как они записаны в файле.
- `pelvisX` сдвигает призрак вдоль пола. Ходьбу и постановку стоп ведёт бой, призрак их не повторяет.

**Высота таза.** Таз у призрака не правится. Тело поднято так, чтобы подошва стояла на полу — это правило игры
(`Rig::getStandingRoot`): согни колени — таз опустится. Игра сверх этого опускает таз к оставленной стопе
(`getReachDrop`, `plantFeet` — при ходьбе и шагах); в стойке без шагов этого нет, так что по высоте призрак
стойки и стоящий боец совпадают. Какая стопа впереди, игра решает сама (`legStep.stanceAfterStop`); призрак
показывает ноги, как они записаны.

### 7.3. Панели

| Панель | Что делает |
|---|---|
| Timeline | `play` — цикл по времени клипа; `speed` 0,05×…1× (кнопки 0.1x/0.25x/0.5x/1x, по умолчанию 0,25×) меняет только показ; ползунок времени (чёрточки — ключи, красная полоса — `active`); `add key here` — ключ в текущий момент с позой клипа в нём; `duplicate` — копия выбранного ключа на полпути до следующего; `delete` (первый и единственный ключ не удаляются); список ключей: клик выбирает ключ, поле `t` двигает его между соседями |
| Key | слайдеры углов выбранного ключа в градусах, только суставы клипа; пределы — `limits` рига (ноги тоже) и `wristLimits`; значение вне пределов красное, ввод с клавиатуры обрезается; наведённый слайдер подсвечивает часть; copy/paste позы; `onion skin` |
| Clip | `loop`, `duration`, `active`, `stiffness`, `allowMove`, `blendIn`/`blendOut` (галочка — поле есть в файле), `strikers`; «joints in the clip» — добавить или убрать сустав во всех ключах (и `key all legs` — все шесть суставов ног; новый стартует там, где он у призрака); `pelvisX` (ключи `t`/`x`, добавить в текущий момент); Undo/Redo; `Help` |
| Open | выбор бойца, клипа, предмета; новый клип (7.6, 7.13) |
| Fact | слой факта и его шаги (7.7), галочки путей, метрик и предупреждений, `compare with` |
| Metrics, Warnings | замер удара и предупреждения (7.8, 7.10); открываются галочками в Fact, закрываются крестиком |
| Help | все горячие клавиши (`F1` или галочка в Clip) |

Кнопка Save недоступна, пока клип не проходит проверку загрузчика; причина пишется красным.

### 7.4. Мышь

Над панелью мышь принадлежит ImGui; на сцене она правит выбранный ключ.

| Что тянуть | Что происходит |
|---|---|
| часть тела (корпус, голова, руки, части ног) | её сустав поворачивается на угол, на который курсор повернулся вокруг него, в пределах сустава; ниже по цепочке всё едет вместе |
| голубой кружок на кулаке | IK руки (плечо + предплечье, аналитически): кулак ставится в точку; недостижимая — рука тянется к ней; углы в пределах рига |
| оранжевый кружок на кончике клинка | кулак на месте, поворачивается запястье (`Weapon`); упёрлось в предел — остаток берёт локоть, затем плечо (кулак тогда сдвигается) |

- **Какой ключ.** Если ползунок не на ключе, при нажатии время встаёт на ближайший ключ (строка статуса пишет, на какой).
  Сустав, которого в клипе ещё нет, добавляется во все ключи с углом, который был у призрака: остальные ключи не меняются.
- **Сгиб локтя.** Галочка `IK: elbow up` (панель Key) или `E` выбирает сгиб IK. Они есть, только если локти рига
  гнутся в обе стороны; у гуманоида локоть гнётся в одну (0…150°), и их нет.
- **Двуручное оружие** (`greatsword`, `war_hammer`). Вторая рука по IK держится за рукоять — точку `grip_m` от кулака
  (голубая точка). Любая правка, двигающая оружие, заново ставит на рукоять кулак второй руки; своей ручки у него нет.
- **Переставленные руки.** Ручки двигают руку, которая на призраке держит оружие; углы пишутся в суставы клипа,
  как они названы в файле (`editor/pose_drag.hpp`).
- Таз мышью не правится; ног-IK и ручки стопы нет.

**Руки по ролям.** Слайдеры рук названы по роли: «weapon arm» (держит оружие на призраке, `weapon.part` рига)
и «other arm». В файле правятся суставы клипа, как они там названы (`editor/arm_roles.hpp`).

### 7.5. Ноги и стойки

Ноги правятся слайдерами (`ThighL/ShinL/FootL/ThighR/ShinR/FootR`), галочками «joints in the clip» и мышью.

Так правятся стойки оружия (`stance_sword`, `stance_hammer`, `stance_greatsword`, `stance_shield`) и общая `stance`:
это клипы без ударов, у которых заданы все шесть суставов ног. Пока правится сама стойка, база призрака — она же.

**Ключи ног в обычном клипе** (удар, блок) делают его действием ногами: игра ставит ноги из клипа и добавляет шаги к позе
([MECHANICS.md](MECHANICS.md), раздел 2). Поэтому, как только в клип без ног добавлены суставы ног, панель Clip
пишет жёлтое предупреждение; оно гаснет после сохранения или когда ноги убраны.

### 7.6. Выбор в окне (панель Open)

| Выбор | Что делает |
|---|---|
| fighter | боец из `data/fighters`: в руки — его оружие и щит, открывается стойка его набора. Набор и стойка ищутся кодом игры (`editor::findStance`: `MoveLibrary::selectSet` по предметам рук; стойка набора или родителя, иначе `stance`). Рядом с клипом — кто им пользуется: `stance_hammer - used by: Knight (moveset hammer)` |
| clip | клип из `data/poses`, список с поиском по подстроке; предметы остаются |
| item | предмет в руках (оружие, щит или голые руки), клип остаётся; `open the stance of these items` — стойка набора этих предметов |
| move (панель Fact) | удар из `data/moves` с этим клипом (`clip` или `close_clip`), который играет факт; по умолчанию первый, который запускает оружие; сбрасывается при открытии другого клипа |

`stance_shield` сейчас не использует ни один боец (щит один набора не даёт); править её можно через список клипов
с предметом `wooden_shield`. Боец с мечом и щитом показывается с обоими, а факт идёт с оружием основной руки.

Переключение с несохранёнными правками спрашивает: **Save**, **Discard** или **Cancel**.
После открытия время встаёт на 0, ключ — на первый, факт считается заново.

### 7.7. Факт

Факт — тот же клип, сыгранный физикой стенда удара; рисуется полупрозрачным розовым поверх призрака.

- Боец стенда делает удар: первый из `data/moves`, чей `clip` или `close_clip` — этот клип и который запускает
  набор предмета из `--weapon`. `close_clip` играется с соперником ближе `close_range_m`.
- Играется клип **из памяти**, с несохранёнными правками, а не файл. Видно, где моторы не дотягивают,
  опаздывают или проскакивают.
- Клип, который не играет ни один удар (стойка, блок, ходьба), факта не имеет; панель пишет почему.

**Время факта.** Кадр факта — один шаг физики (1/60 с) от начала удара; время — время клипа после шага.
Оно идёт со скоростью удара (`x…` в панели: ловкость бойца стенда и оружие) и стоит, когда удар остановлен
попаданием. Момент `t` таймлайна показывает первый шаг, где время клипа дошло до `t`; после конца удара —
последний шаг. В начале факт ещё в пути от стойки (`blendIn`). Таз факта в начале удара — там же, где таз призрака.

**Пересчёт.** Каждая правка (мышь, слайдер, ключ, поле клипа, `F5`) сбрасывает кадры, и удар считается
с начала стенда (бойцы стоят `settle_sec`, затем ввод). Пока мышь или слайдер держат правку, факт показывает
прежний расчёт. Считается только до показанного момента; посчитанные шаги берутся из кеша (шаг детерминирован).

| Элемент панели Fact | Что делает |
|---|---|
| `ghost`, `fact` | показывать призрак / факт (без призрака мышь не правит) |
| `dummy` | манекен стенда напротив (серый, в `ai.range_m` удара), иначе соперник далеко; переключение — пересчёт |
| `< step (,)`, `step > (.)` | шаг физики назад / вперёд; время встаёт на время клипа этого шага |
| строки | удар, ввод, предмет; шаг (`+` — дальше ещё не считали), время клипа и фаза, скорость клипа; худший сустав верха тела (угол факта минус угол цели; ноги и наклон таза не сравниваются); под «joints» — все суставы |
| `ghost path`, `fact path`, `metrics`, `warnings`, `compare with` | пути кончика, панели Metrics и Warnings, клип для сравнения |

### 7.8. Метрики

Панель Metrics — замер удара на стенде (`combat::MoveMeasure`, строки — `editor::listMetrics`).

| Строка | Что значит |
|---|---|
| startup / active / recovery / total | реальные секунды: DEX, оружие и выносливость учтены |
| reach | дальше всего вперёд от таза в активной фазе и какая часть |
| tip speed | пик и средняя по активной фазе, м/с, у кончика самой дальнобойной части (`findTipSpeed`) |
| pelvis | вперёд / назад от таза в начале удара и где таз остался |
| hit, contact | попал ли удар по манекену: часть, время, урон, реакция, скорость сближения, импульс, сила |

Это тот же прогон, что факт: клип из памяти, без сохранения. Столбцы: текущая настройка манекена,
другая настройка и клип для сравнения. Другая настройка — второй прогон (≈ 0,4 с в debug); он считается
только по кнопке `measure` и живёт, пока не изменились клип, удар или манекен. Текущий прогон считается
после правки (когда мышь отпущена) и только пока панель открыта.

### 7.9. Траектории

Путь кончика ударной части: `ghost path` — цель, `fact path` — физика.

| Путь | Цвет | Активная фаза |
|---|---|---|
| призрак (по клипу с шагом `trajectory_step_sec`, с дорожкой таза) | голубой | оранжевый |
| факт (каждый шаг прогона, по времени клипа) | розовый | жёлтый |

Точка — один отсчёт, кольцо — текущее время. Кончик — как у стенда (раздел 5). Если ударных частей несколько,
берётся та, чей кончик прошёл дальше (у факта — и среди зеркальных). Путь факта сдвинут так же, как тело факта.

### 7.10. Предупреждения

Панель Warnings — советы автору, не ошибки: сохранение они не блокируют. Клик по строке ставит время на место.

| Предупреждение | Когда | Источник |
|---|---|---|
| `the tip of X is N cm below the floor` | кончик ударной части ниже пола больше чем на `tip_floor_margin_m`; время — самая низкая точка | призрак и факт |
| `at limit at T s: ...` | угол сустава или запястья в ключе ближе `limit_margin_deg` к пределу или за ним; строка на ключ со списком суставов и пределом. Прямые локоть и колено (предел 0°) не в счёт; у таза пределов нет | клип |
| `the active phase is empty` / `ends past the end of the clip` | `active` пустое или кончается после `duration` | клип |
| `no striking parts` | нет `strikers` | клип |
| `the move strikes with the weapon, but the strikers are not a forearm` | удар с `uses_weapon` без предплечья в `strikers`; то же правило, что в `--check-data` (`combat::findStrikeProblems`) | клип |
| `fact: X is N deg off the target during the active phase` | в активной фазе сустав верха тела факта дальше `divergence_deg` от цели; строка на самом плохом шаге | факт |

Предупреждения клипа и призрака считаются каждый кадр. Предупреждения факта — раз после правки, прогоном до конца
удара (≈ 0,4 с в debug); галочка `check the fact (runs the move)` отключает это. Пороги — `data/editor.json`
([TUNING.md](TUNING.md#17-стенд-и-редактор-поз), [DATA_FORMATS.md](DATA_FORMATS.md#16-editorjson--пороги-редактора-поз)).

### 7.11. Сравнение

`compare with` — второй клип из `data/poses`, показанный тусклым вторым призраком.

Он идёт на том же времени (не дальше своей длительности), с тем же бойцом, предметами и стойкой. Галочка `its path` —
его путь кончика; в Metrics — свой столбец. Ничего не правится. Выбор сбрасывается при открытии другого клипа.

### 7.12. История, копирование, onion skin

| Что | Как работает |
|---|---|
| undo / redo | снимки всего клипа (`editor/clip_history.hpp`, до 200 шагов). Шаг — один жест: перетаскивание записывается, когда кнопку отпустили; кнопки правок ключей и поля клипа — по шагу. Откат до сохранённого состояния снимает `(unsaved)`. Открытие другого клипа и `F5` начинают историю заново; сохранение — нет |
| копирование позы | `Ctrl+C` / `Ctrl+V` на выбранном ключе. Вставляются углы суставов, которые есть и в копии, и в клипе (в пределах рига), и запястье, если оно есть у обоих; время ключа и набор суставов не меняются. Копия живёт до выхода и переносится между клипами |
| onion skin | бледные призраки соседних ключей: до — синеватые, после — зеленоватые; `keys` — 1 или 2 с каждой стороны; у цикла соседи идут по кругу |

### 7.13. Горячие клавиши

Простые клавиши не срабатывают, пока фокус в текстовом поле (поиск клипа, имя нового клипа).

| Клавиша | Действие |
|---|---|
| `Ctrl+S` (на macOS и `Cmd+S`) | сохранить |
| `F5` / `Shift+F5` | перечитать клип с диска / то же при несохранённых правках |
| `Ctrl+Z`; `Ctrl+Shift+Z` или `Ctrl+Y` | отменить; вернуть |
| `Ctrl+C` / `Ctrl+V` | копировать / вставить позу ключа |
| `Left` / `Right` | предыдущий / следующий ключ |
| `K` или `Insert` | ключ в текущий момент |
| `Delete` | удалить выбранный ключ |
| `O` | onion skin |
| `Space` | играть / пауза |
| `,` / `.` | шаг физики факта назад / вперёд |
| `[` / `]` | скорость превью вдвое медленнее / быстрее |
| `E` | сгиб локтя IK (если есть) |
| `F1` | панель Help |

### 7.14. Новый клип

Панель Open, раздел `New clip...`: имя и шаблон.

- Имя — `a-z`, `0-9`, `_`, с буквы, до 48 знаков; существующее имя отклоняется (причина красным).
- Шаблон — открытый клип (с правками), стойка предметов в руках или любая другая `stance*`.
- `Create` открывает копию **несохранённой**; файл `data/poses/<имя>.json` появляется только после Save.
- Копируются все поля шаблона (`loop`, `strikers`, `active`…): для нового удара их надо поправить, Warnings подскажет.
- Факта нет, пока клип не играет ни один удар: привяжите его к удару в `data/moves`.

### 7.15. Вид файла

Сохранение пишет клип своим писателем (`editor/clip_writer.hpp`), всегда в одном виде.

Поля в фиксированном порядке, один ключ на строку, углы без `.0`, времена с одинаковым числом знаков;
правая рука первой, если бьёт правое предплечье. Все файлы `data/poses` в этом виде, и тест
`Every clip of data/poses...` требует, чтобы каждый записывался байт в байт. Новый клип лучше сразу делать в редакторе.
