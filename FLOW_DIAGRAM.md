## 🔗 Взаимодействие модулей

### **Схема связей**

```
                    ┌─────────────────────────────────────────────────┐
                    │              EventManager                       │
                    │  (Центральный диспетчер событий)               │
                    └─────────────────────────────────────────────────┘
                                    │
                    ┌───────────────┼───────────────┐
                    │               │               │
            ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
            │PhysicsModule │  │GraphicsModule│  │FightController│
            │             │  │             │  │             │
            └─────────────┘  └─────────────┘  └─────────────┘
                    │               │               │
                    │               │               │
            ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
            │   Entity    │  │  Drawable   │  │    Fight    │
            │             │  │             │  │             │
            └─────────────┘  └─────────────┘  └─────────────┘
                    │               │               │
                    └───────────────┼───────────────┘
                                    │
                            ┌─────────────┐
                            │ GameObject  │
                            │ (Мост между │
                            │  движками)  │
                            └─────────────┘
                                    │
                            ┌─────────────┐
                            │Coordinate   │
                            │System       │
                            └─────────────┘
```

### **Типы связей**

- **🔴 Наследование** (is-a): `Fighter : Entity`, `DrawableSprite : Drawable`
- **🔵 Композиция** (has-a): `PhysicsModule` содержит `vector<Entity*>`
- **🟡 Агрегация** (uses-a): `FightController` использует `PhysicsModule&`
- **🟢 Ассоциация** (knows-a): `EventManager` знает о всех модулях
- **🟣 Множественное наследование**: `GameObject : DrawableSprite, Entity`

## 📊 Временные характеристики

### **Частота обновления**

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                    ВРЕМЕННАЯ СХЕМА                                                       │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│  EventManager::Clock() вызывается каждые 10ms (100 FPS)                                                 │
│  ├─ PhysicsModule::updateObjects(dt) - обновление физики                                                │
│  ├─ GraphicsModule::TimeEvent(dt) - обновление графики                                                  │
│  └─ FightController::timeEvent(dt) - игровая логика                                                     │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│  SFML события обрабатываются в реальном времени                                                          │
│  ├─ KeyPress/Release - мгновенно                                                                        │
│  ├─ MouseMove - при движении мыши                                                                       │
│  └─ Window events - при изменении окна                                                                  │
├─────────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│  Синхронизация физики и графики происходит автоматически                                                │
│  ├─ GameObject::updateGraphicsPosition() - при изменении физических свойств                              │
│  ├─ CoordinateSystem - конвертация координат                                                            │
│  └─ SFML рендеринг - при вызове GraphicsModule::draw()                                                 │
└─────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 🎯 Ключевые особенности потоков

### **1. Событийно-ориентированная архитектура**
- Все взаимодействия происходят через `EventManager`
- Слабая связанность между модулями
- Легко добавлять новые типы событий

### **2. Автоматическая синхронизация**
- `GameObject` автоматически синхронизирует физику и графику
- `CoordinateSystem` обеспечивает конвертацию координат
- Нет необходимости вручную обновлять позиции спрайтов

### **3. Оптимизированная физика**
- `SpatialGrid` для быстрого поиска коллизий
- Множественные итерации для стабильности
- Эластичные коллизии и трение

### **4. Модульная структура**
- Каждый модуль отвечает за свою область
- Легко тестировать и отлаживать
- Возможность замены модулей

### **5. Производительность**
- Отрисовка только видимых объектов
- Оптимизированные алгоритмы коллизий
- Эффективное управление памятью
